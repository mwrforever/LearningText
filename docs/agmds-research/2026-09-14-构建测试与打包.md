## 一、技术概况（逐主题要点，均带来源 URL）

### 1. Vite：CLI 命令、构建产物目录、env/mode 机制

来源：
- CLI（官方）：https://vite.dev/guide/cli
- env 与 mode（官方）：https://vite.dev/guide/env-and-mode
- 构建（官方）：https://vite.dev/guide/build

要点：

- **命令**：`vite [root]`（开发服务器）、`vite build [root]`（生产构建）、`vite preview [root]`（本地预览 `dist` 产物；官方警告**不得用作生产服务器**）、`vite optimize [root]`（已标记废弃，依赖预打包会自动执行）。官方明确 **`vite dev` 与 `vite serve` 是 `vite` 的别名**。
- **常用 flag**：dev/preview 共用 `--host`、`--port`、`--open`、`--strictPort`；build 侧 `--outDir`（默认 `dist`）、`--base`（默认 `/`）、`--watch`、`--emptyOutDir`、`--sourcemap`、`--target`、`--minify`（Vite 8 默认 `"oxc"`）；各命令共享 `-c/--config`、`-m/--mode`、`-l/--logLevel`。
- **npm scripts 官方示例**：`"dev": "vite"`、`"build": "vite build"`、`"preview": "vite preview"`；scripts 内可直接写 `vite`（npm 会把 `node_modules/.bin` 加入 PATH），与 `npx vite` 等价。
- **构建产物**：默认输出到 `dist`（`build.outDir` 默认值；CLI `--outDir` 文档同标）。`build.assetsDir` 与 `emptyOutDir` 的精确默认值本次未从配置参考页核实到（该页为构建高级用法页），记 {待调研项}。
- **env/mode**：加载 `.env`、`.env.local`（git 忽略）、`.env.[mode]`、`.env.[mode].local` 四类文件；**只有 `VITE_` 前缀的变量会暴露给客户端代码**（`import.meta.env.VITE_*`），其余为 `undefined`；shell 已存在的环境变量优先级最高，不会被 .env 覆盖；.env 在启动时加载，改后需重启。**mode 与 NODE_ENV 是两个概念**：`vite build` 默认 NODE_ENV=production + mode=production，`--mode staging` 只改 mode，`import.meta.env.PROD/DEV` 由 NODE_ENV 决定。
- 敏感信息（密钥等）禁止用 `VITE_` 前缀——会被静态打包进产物源码。

### 2. Vitest：CLI、默认测试文件匹配、projects、环境、覆盖率（v5 要点）

来源：
- 覆盖率指南（官方）：https://vitest.dev/guide/coverage
- 覆盖率配置参考（官方）：https://vitest.dev/config/coverage
- 测试环境（官方）：https://vitest.dev/guide/environment
- 迁移指南 v5.0（官方）：https://vitest.dev/guide/migration
- CLI（官方，`vitest run` 一次性模式）：https://vitest.dev/guide/cli
- 主配置（`include` 默认值佐证）：https://vitest.dev/config/

要点：

- **v5.0 硬性前置**：要求 **Vite >= 6.4.0、Node >= 22.12.0**（engines 实测 `^22.12.0 || ^24.0.0 || >=26.0.0`）。不满足即不受支持。
- **CLI**：`vitest`（交互/监听）与 `vitest run`（一次性运行，CI 用）；覆盖率加 `--coverage`（或 dot 写法 `--coverage.enabled --coverage.provider=istanbul`，此时必须显式 `--coverage.enabled`）。
- **测试文件默认匹配**：`include` 默认 `['**/*.{test,spec}.?(c|m)[jt]s?(x)']`——已在 vitest 5.0.0 发布包源码中核实（`node_modules/vitest/dist/config.cjs` 与类型声明的 `@default`），与配置文档一致。
- **projects（多项目）**：v5 通过主配置的 `test.projects` 组织（如 `name: 'unit'` / `name: 'integration'` 各配 `include`）；`vitest.workspace.ts` 已被该机制取代（v4/v5 迁移文档均只描述 `test.projects`）。**v5 起 inline project 默认继承根配置**（`extends` 默认 `true`），根配置的 `plugins`、`setupFiles`（数组合并追加）会下发到各 project。
- **环境**：默认 `node`；内置可选 `jsdom`、`happy-dom`（官方注明 happy-dom 更快但 API 覆盖少）、`edge-runtime`，各自需安装对应 npm 包；可用文件头注释 `// @vitest-environment jsdom` 对单文件切环境。渲染层组件测试才需要 DOM 环境，主进程/共享逻辑测试用默认 node 即可。
- **覆盖率 provider**：`v8`（**默认**，无需预转译、更快、内存更低）与 `istanbul`（插桩，兼容任意 JS 运行时、更慢）；支持包 `@vitest/coverage-v8` / `@vitest/coverage-istanbul`，首次运行会提示自动安装。**peerDependencies 实测锁定 vitest 精确版本（5.0.0 === 5.0.0）**，升级 vitest 必须同步升级 coverage 包。
- **覆盖率报告**：`coverage.reportsDirectory` 默认 `./coverage`，且 `coverage.clean` 默认 `true`——**每次运行前会删除该目录**；`reporter` 默认 `['text', 'html', 'clover', 'json']`。
- **覆盖率范围**：默认只统计测试运行中被 import 的文件；要统计未被测试引用的文件（门禁场景必需），必须显式配置 `coverage.include`（如 `src/**/*.{ts,tsx}`）。
- **thresholds**：`coverage.thresholds` 支持 `lines/functions/branches/statements`（正数=最低百分比，**负数=允许的未覆盖项上限**）、`perFile`（逐文件检查）、`100`（四项一键 100）、`thresholds[glob]`（按 glob 分组设阈值；注意匹配 glob 的文件**同时计入全局阈值**，与 Jest 行为不同）、`autoUpdate`（覆盖率变好时自动回写配置）。
- **v5 其他行为变化（影响测试写法规范）**：`clearMocks` 默认 `true`（每个测试前清空调用记录）；`vi.mock/vi.hoisted` 必须写在模块顶层（嵌套调用从警告升级为抛错）；未 `await` 的异步断言（`.resolves/.rejects`）现在直接判失败；报告产物统一收敛到项目根 `.vitest/` 目录（.gitignore 一条即可）。

### 3. Playwright：`_electron` API、test CLI、trace 调试、浏览器安装

来源：
- Electron 支持 `_electron`（官方）：https://playwright.dev/docs/api/class-electron
- ElectronApplication 类（官方）：https://playwright.dev/docs/api/class-electronapplication
- 命令行（官方）：https://playwright.dev/docs/test-cli
- Trace Viewer（官方）：https://playwright.dev/docs/trace-viewer

要点：

- **`_electron.launch(options)`**：返回 `Promise<ElectronApplication>`；关键参数 `args`（官方提示"通常在这里传主脚本路径"）、`executablePath`（**缺省用 `node_modules/.bin/electron`**）、`env`（默认继承 `process.env`）、`timeout`（默认 30000ms）、`cwd`、`recordVideo`、`recordHar` 等。支持 Electron v12.2.0+/v13.4.0+/v14+。
- **常用流程**：`launch` → `electronApp.firstWindow()`（必要时等待首个窗口）→ 对窗口（Page）执行 locator 断言/操作 → `electronApp.close()`。`electronApp.evaluate(callback)` 在**主进程**内求值（参数即主进程的 `require('electron')` 结果），可读取 `app.getAppPath()` 等。
- **原生对话框**：Playwright 不拦截 `dialog.showOpenDialog` 等原生 API；官方做法是在主进程内用 `electronApp.evaluate(({ dialog }) => { dialog.showOpenDialog = () => Promise.resolve({...}) })` 替换，替换持续到应用关闭。
- **启动卡死排查**：若 Electron 启动超时，检查 fuse `EnableNodeCliInspectArguments` 未被关闭。
- **test CLI**：`npx playwright test [options] [test-filter...]`，常用 `--headed`、`--ui`、`--debug`（等价 `PWDEBUG=1 --timeout=0 --max-failures=1 --headed --workers=1`）、`-g/--grep`、`--project`、`--workers`（默认逻辑核 50%）、`--retries`、`--trace <mode>`（on/off/on-first-retry/on-all-retries/retain-on-failure 等）、`--reporter`、`--output`（默认 `test-results`）、`--update-snapshots`、`--last-failed`、`--list`、`--shard`、`--forbid-only`（CI 防 `test.only`）、`--pass-with-no-tests`；文件过滤器支持 `tests/todo-page.spec.ts`、`my-spec.ts:42`（行号）写法。`npx playwright show-report`（默认端口 9323）看 HTML 报告。
- **trace**：CI 首选在配置中 `trace: 'on-first-retry'`（配合 `retries`）；本地调试 `--trace on` 后经 `show-report` 或 `npx playwright show-trace trace.zip` 打开；trace 含 Actions/DOM 快照/截图胶片/Console/Network/Source 等。另有网页版 trace.playwright.dev（本地加载，数据不出端）。
- **浏览器安装**：`npx playwright install [browser...]`、`npx playwright install --with-deps`（连同 Linux 系统依赖）、`npx playwright install-deps`、`npx playwright uninstall`、`--dry-run` 可预演。
- **与 Electron E2E 的关系（推断，官方未明文）**：`_electron` 驱动的是应用自带的 Electron 可执行文件（executablePath 默认 `node_modules/.bin/electron`），E2E 不使用 Playwright 下载的浏览器二进制；Linux runner 的系统依赖是否需要 `install-deps` 官方 Electron 页未述，记 {待调研项}，CI 侧先按"无需浏览器下载"落方案、失败再补依赖（见 CI 专项报告）。

### 4. electron-builder：配置文件、目录约定、CLI 与 `--dir` 冒烟

来源：
- CLI（官方）：https://www.electron.build/cli
- 配置文档（官方）：https://www.electron.build/configuration
- 配置默认值源码（官方仓库 `app-builder-lib/src/configuration.ts`，`MetadataDirectories` 接口）：https://github.com/electron-userland/electron-builder/blob/master/packages/app-builder-lib/src/configuration.ts

要点：

- **配置文件位置与命名**：`--config` 默认 **`electron-builder.yml`**；支持 `yml/json/json5/toml/js/ts`，或直接写在 `package.json` 顶层 `build` 字段。注意：JS 配置**不可命名 `electron-builder.js`**（与包名冲突）；TOML 需另装 `toml` 依赖；`electron-builder.env` 文件仅 CLI 方式生效。
- **目录约定**（源码注释原文）：`directories.buildResources` 默认 **`build`**（放图标、DMG 背景、license、自定义 NSIS 脚本等静态资源；**不会拷贝进打包产物**，运行时需要的资源要走 `files` 选项）；`directories.output` 默认 **`dist`**（安装包/压缩包输出；支持宏如 `dist/${os}-${arch}`）。
- **CLI 命令**：`electron-builder build`（默认命令）、`install-app-deps`（为应用安装/重编原生依赖）、`node-gyp-rebuild`、`create-self-signed-cert`、`publish`。构建 flag：`--mac/-m`、`--linux/-l`、`--win/-w`、`--x64/--arm64/--universal`、**`--dir`（官方说明："Build unpacked dir. Useful to test."——冒烟打包）**、`--prepackaged`、`--projectDir`、`-c/--config`、`-c.extraMetadata.foo=bar`（命令行覆写配置）。
- **发布**：`--publish`（choices：`onTag`/`onTagOrDraft`/`always`/`never`）；全平台一键 `electron-builder -mwl`。
- **默认目标**：macOS=DMG+ZIP(Squirrel.Mac)、Windows=NSIS、Linux=Snap+AppImage；可在配置里按平台声明 `target`/`arch`。
- **版本预警**：官方 master 文档注明 **v27 将把 `electronDownload` 配置更名为 `electronGet`**（对齐 @electron/get v5 选项结构）；v27 尚未发布稳定版（当日最新 26.15.3），升级时需复核。

### 5. husky v9 与 lint-staged：本地 pre-commit 门禁

来源：
- husky 入门（官方）：https://typicode.github.io/husky/get-started.html
- husky How-To（官方）：https://typicode.github.io/husky/how-to.html
- lint-staged README（官方）：https://github.com/lint-staged/lint-staged

要点：

- **husky 安装（v9 现行步骤）**：`npm install --save-dev husky` → `npx husky init`（自动在 `.husky/` 生成 `pre-commit` 示例并**把 package.json 的 `prepare` 脚本设为 husky**）→ 提交 `.husky/` 与 `package.json`。How-To 手动步骤同样给出 `"prepare": "husky"`（npm 场景标准写法）。
- **钩子文件写法**：`.husky/pre-commit` 内直接写 POSIX shell 命令（官方示例 `echo "npm test" > .husky/pre-commit`，**现行文档已无 shebang / `husky.sh` 引用**）；官方明确 **钩子脚本需 POSIX 兼容**（团队有 Windows 用户时不保证 bash 可用）。
- **禁用与 CI**：单次跳过 `git commit -n` 或 `HUSKY=0 git ...`；CI/Docker 官方建议 env `HUSKY: 0`；`npm ci --omit=dev` 场景 `prepare` 可能因 husky 未装而失败，官方给两种解法：`"prepare": "husky || true"`，或改用 `.husky/install.mjs`（NODE_ENV=production / CI 时直接 `process.exit(0)`）+ `"prepare": "node .husky/install.mjs"`。
- **GUI/版本管理器**：GUI 提交时 PATH 缺失会导致钩子失败，解法是把 nvm 等初始化写入 `~/.config/husky/init.sh`（husky 每次钩子前 source 它）。
- **lint-staged**：安装后**无需 init**，配置可放 `package.json` 的 `lint-staged` 字段、`.lintstagedrc(.json/.yaml/.yml)`、`.lintstagedrc.(mjs|cjs|js)`、`lint-staged.config.(mjs|cjs|js)` 或 `--config` 指定；JS 配置可用 `defineConfig`（`lint-staged/config`）获得类型。配置形如 `{"*.{ts,tsx}": ["eslint --fix", "prettier --write"]}`；同 glob 多命令用数组**串行**执行，不同 glob 默认并行——**glob 重叠且都改文件时会有竞态**，官方给出取反 glob + 数组的解法（`"!(*.ts)": "prettier --write", "*.ts": ["eslint --fix", "prettier --write"]`）。任务修改会自动加入提交（v10 起禁止再写 `git add`，会被警告）。
- **lint-staged 常用 CLI**：`--diff="main...HEAD"`（CI 中跑变更文件）、`--concurrent <n|false>`、`--relative`、`--max-arg-length`（Windows 命令行长度分片，自动处理）、`--no-stash`、`--fail-on-changes`、`npx lint-staged --all`（CI 全量）。
- **配合要点**：`.husky/pre-commit` 内只写一行 `npx lint-staged`（不要自己传文件名参数）；ESLint flat config 场景对被 ignore 的文件加 `--no-warn-ignored` 避免警告中断；对 `tsc --noEmit` 这类**不能接文件名参数**的命令用函数形式 `() => 'tsc --noEmit'`（直接传文件名会让 tsc 忽略 tsconfig）。

### 6. ESLint 10 flat config + typescript-eslint + Prettier

来源：
- ESLint 配置文件（官方）：https://eslint.org/docs/latest/use/configure/configuration-files
- ESLint v10.0.0 发布公告（官方博客，eslintrc 移除）：https://eslint.org/blog/2026/02/eslint-v10.0.0-released/
- typescript-eslint 快速开始（官方）：https://typescript-eslint.io/getting-started
- Prettier 与 Linter 集成（官方）：https://prettier.io/docs/en/integrating-with-linters

要点：

- **flat config 一统**：ESLint **v10 起 eslintrc 体系彻底移除**（`ESLINT_USE_FLAT_CONFIG` 逃生门也随之取消），唯一配置系统为 `eslint.config.(js|mjs|cjs|ts|mts|cts)`，放仓库根，导出配置对象数组；同目录多种后缀时优先级 `js > mjs > cjs > ts`。TS 配置文件需 `jiti >= 2.2.0`，或 Node >= 22.13 配 `--experimental-strip-types` + `unstable_native_nodejs_ts_config` flag。
- **配置结构**：推荐用 `defineConfig`（`eslint/config` 内置 helper）组织数组；`files` 限定作用文件、`ignores` 独占一个对象时为**全局忽略**（官方推荐 `globalIgnores()` helper 显式表达）；内置默认忽略仅 `**/node_modules/` 与 `.git/`，**`dist`、`coverage`、`node_modules` 之外的产品目录必须在配置中显式 globalIgnores**。预置规则集 `js.configs.recommended`（来自 `@eslint/js`）；ESLint 运行 `eslint .` 即从当前目录开始 lint。
- **typescript-eslint**：装元包 `typescript-eslint`（统一入口，内含 parser/plugin/utils）；官方 flat config 起手式 `defineConfig({ files: ['**/*.{js,ts}'], extends: [js.configs.recommended, tseslint.configs.recommended] })`；`strict` 是 `recommended` 的超集；类型感知规则集（`recommendedTypeChecked`/`strictTypeChecked`）配合 `parserOptions.project`/`projectService` 使用（见 Typed-Linting 专页：https://typescript-eslint.io/getting-started/typed-linting ）。**peerDependencies 实测：eslint `^8.57.0 || ^9.0.0 || ^10.0.0`、typescript `>=4.8.4 <6.1.0`**——与 ESLint 10 兼容。
- **Prettier 集成的现行官方建议**：原则"**Prettier 管格式、Linter 管质量**"；用 **eslint-config-prettier** 关闭与 Prettier 冲突/多余的样式规则；**不再推荐 eslint-plugin-prettier**（把 Prettier 当 ESLint 规则跑：编辑器满屏波浪线、比直接跑慢、多一层间接），现在直接 `prettier --check .` 即可；两者并行运行、各司其职。

### 7. npm 生命周期脚本、工具链 Node 版本要求、Electron 二进制环境变量

来源：
- npm scripts 生命周期（官方）：https://docs.npmjs.com/cli/v11/using-npm/scripts
- 各包 engines 字段（npm registry，当日实测）
- @electron/get README（官方）：https://github.com/electron/get
- Electron 安装文档（官方仓库）：https://github.com/electron/electron/blob/main/docs/tutorial/installation.md
- electron 包安装脚本源码（官方仓库）：https://github.com/electron/electron/blob/main/npm/install.js
- @electron/rebuild README（官方）：https://github.com/electron/rebuild

要点：

- **`prepare` 脚本时机**：本地无参数 `npm install` 时运行（`--omit=dev` 也运行，但装单个包不运行）；装 git 依赖时在打包前运行；`npm publish/pack` 时在 prepack 之后、postpack 之前运行——husky 依赖该机制实现"装完依赖钩子自动就位"。
- **工具链 Node engines 实测（决定 Node pin 下限）**：vite `^20.19.0 || >=22.12.0`；vitest `^22.12.0 || ^24.0.0 || >=26.0.0`；eslint `^20.19.0 || ^22.13.0 || >=24`；**lint-staged `>=22.22.1`**；playwright/@playwright/test `>=20`；typescript-eslint `^18.18.0 || ^20.9.0 || >=21.1.0`；husky `>=18`；electron-builder `>=14`。**全链路交集落在 Node 22.22.1+ 或 24 LTS；Vitest 5 额外要求 Vite >= 6.4**。
- **Electron 二进制下载**：`electron` 包安装时由 postinstall 脚本经 `@electron/get` 下载平台二进制；镜像变量 `ELECTRON_MIRROR`（官方给出中国镜像示例 `https://npmmirror.com/mirrors/electron/`）、`ELECTRON_CUSTOM_DIR`、`ELECTRON_CUSTOM_FILENAME`（URL 拼接公式 `MIRROR + CUSTOM_DIR + '/' + CUSTOM_FILENAME`）、`ELECTRON_GET_USE_PROXY`、`electron_config_cache`（缓存路径覆盖）、`ELECTRON_OVERRIDE_DIST_PATH` 等（见安装文档与 @electron/get README）。
- **重要证伪——`ELECTRON_SKIP_BINARY_DOWNLOAD`**：该变量在 **当前 electron 包 `npm/install.js` 中已不存在**（主 README 与安装文档亦无记载，脚本改为 `isInstalled()` 校验通过即跳过下载，另支持 `ELECTRON_OVERRIDE_DIST_PATH` 指向既有 dist）。旧教程/CI 缓存方案若依赖该变量需改写。离线/CI 场景应使用 `ELECTRON_MIRROR`、缓存目录变量或 `ELECTRON_OVERRIDE_DIST_PATH`。
- **原生模块重编译**：`@electron/rebuild`（当日 4.2.0，要求 Node >= 22.12）为 Electron ABI 重编译原生模块，`-f` 强制、`-w` 指定模块；electron-builder 的 `npmRebuild` 默认 `true` 会在打包前自动执行（详见 CI 专项报告）。

## 四、关键发现摘要（供宪法编写者速览）

1. **版本基线全面更新**：Vite 8.3 / Vitest 5.0 / ESLint 10.10 / lint-staged 17.5，均新于 CI 专项报告撰写时的部分印象版本；Vitest 5 要求 Vite >= 6.4、Node >= 22.12。
2. **Node pin 结论素材**：全工具链 engines 交集为 Node 22.22.1+ 或 24 LTS，建议钉 24 LTS（.nvmrc + engines 双写）。
3. **`ELECTRON_SKIP_BINARY_DOWNLOAD` 已证伪**：当前 electron 安装脚本不再检查该变量；离线/镜像场景应使用 `ELECTRON_MIRROR`、`ELECTRON_OVERRIDE_DIST_PATH`、`electron_config_cache`。
4. **ESLint 10 仅 flat config**：eslintrc 彻底移除；与 Prettier 集成的官方现行建议只用 eslint-config-prettier，不引入 eslint-plugin-prettier。
5. **`dist/` 目录名冲突**：Vite 渲染层与 electron-builder 输出默认同为 `dist/`，目录规划（如 electron-builder output 改 `release/` 或 Vite outDir 改 `dist/renderer/`）是宪法必须裁决的点（本次仅呈现事实，未做取舍）。
6. **覆盖率门禁三要素**：provider v8（默认）+ 显式 `coverage.include`（否则漏测文件不计入）+ thresholds（支持 perFile/100/glob 分组）；coverage 包版本必须与 vitest 严格一致。
7. **冒烟打包**：electron-builder `--dir`（"Build unpacked dir. Useful to test."）即官方打包冒烟命令，可与 CI 方案 A 的打包冒烟步骤直接对接。
