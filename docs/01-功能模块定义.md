## 1. 产品定位

LearningText 是一款**跨平台桌面端 HTML 文档管理与实时预览工具**，面向以 HTML 形式整理、编写学习笔记与资料的个人用户。核心体验：

1. 所有文档（HTML/CSS/JS/图片等）保存在**一个本地 SQLite 数据库**中，由自建的**虚拟文件系统（VFS）**统一管理，不散落在真实磁盘目录里；
2. **所见即所得编辑 HTML**（2026-09-22 修订）：直接在渲染结果上编辑（Typora 式），渲染面即编辑面，且渲染与浏览器打开**完全一致**；
3. 支持对文件名与文档内容的**模糊搜索**，以及创建、重命名、移动、删除等基础文件管理能力。

## 2. 模块总览

| 编号 | 模块名称 | 定位 | 优先级 |
| ---- | ------------------------ | ---------------------------------------- | ---- |
| M1 | 应用外壳模块 | 桌面容器、窗口、菜单、打包分发 | P0 |
| M2 | SQLite 存储引擎模块 | 持久化底座：连接、事务、迁移、备份 | P0 |
| M3 | 虚拟文件系统模块（VFS） | 核心域模型：节点树、路径、CRUD、事务 | P0 |
| M4 | 实时 HTML 渲染预览模块 | 核心卖点：与浏览器一致的实时渲染 | P0 |
| M5 | 编辑器模块 | HTML 所见即所得编辑 + CSS/JS 源码编辑 | P0 |
| M6 | 模糊搜索模块 | 文件名 + 内容全文检索 | P0 |
| M7 | 导入导出模块 | 与真实文件系统互转 | P1 |
| M8 | 辅助功能模块 | 回收站、最近打开、设置、自动备份 | P1 |

依赖关系（箭头表示"依赖于"）：

```text
M1（外壳）
 ├── M5 编辑器 ──┐
 ├── M4 预览 ────┼──→ M3 虚拟文件系统 ──→ M2 SQLite 存储
 ├── M6 搜索 ────┘            │
 ├── M7 导入导出 ─────────────┘
 └── M8 辅助功能 ──→ M2 / M3
```

M2、M3、M6 的服务实现运行在主进程；M4、M5 及各界面运行在渲染进程（详见 03 号文档架构章节）。

## 3. 模块职责与边界

### M1 应用外壳模块

- **职责**：Electron 应用生命周期管理；主窗口创建与 **VS Code 式布局**（2026-09-22 修订：自绘集成标题栏 + 应用内菜单 / 活动栏 / 侧栏（资源树·搜索·回收站）/ 编辑区标签 / 状态栏 / 欢迎页）；菜单与快捷键；跨平台打包（Windows NSIS 支持选择安装位置 / macOS DMG / Linux AppImage）；自动更新（P2 预留）。
- **边界**：不包含任何业务逻辑；所有业务能力通过 IPC 网关暴露给渲染进程。
- **关键约束**：渲染进程必须开启 `contextIsolation` 与沙箱，渲染进程不持有 Node 能力，只能通过类型化 IPC 访问主进程服务。

### M2 SQLite 存储引擎模块

- **职责**：SQLite 数据库文件的打开/创建、连接管理；WAL 模式与事务封装；数据库结构版本迁移（migration）；定时滚动备份；损坏检测与恢复指引。
- **边界**：只提供"可靠的数据库 + 事务 + 迁移"原语，不理解文件树、搜索等业务概念。
- **关键约束**：全部写操作必须走事务；数据库位置遵循各操作系统标准用户数据目录；单个数据库文件即全部用户数据，可整文件拷贝备份。

### M3 虚拟文件系统模块（VFS）

- **职责**：以"目录/文件统一节点树"建模用户数据；提供创建、读取、写入、重命名、移动、删除（软删除进回收站）、还原、彻底删除等操作；虚拟路径解析（如 `/笔记/web/index.html`）；同目录重名与非法字符校验；保证树操作（移动、重命名子树）的原子性；向渲染层提供 `vfs://` 资源定位规范（与 M4 协作）。
- **边界**：不负责内容检索（M6）、不负责渲染（M4）；不直接操作真实磁盘（互转归 M7）。
- **关键约束**：文件内容以 BLOB 存于数据库内（单文件上限见 03 号文档非功能需求）；所有树结构变更必须在单事务内完成并同步维护路径与全文索引。

### M4 实时 HTML 渲染预览模块

- **职责**：将 VFS 中的 HTML 文档（含其引用的相对路径 CSS/JS/图片）渲染为与浏览器一致的画面，**渲染面同时是所见即所得编辑面**（2026-09-22 修订：向渲染面注入编辑桥脚本——contenteditable + 父子消息协议——承载直接编辑，自己写入引发的变更广播不再重载渲染面以保护光标与撤销）；编辑落库按去抖策略自动保存；开发者工具入口（P1）。
- **边界**：不做语法高亮（M5）、不做内容存储；不实现任何自研 HTML/CSS 排版——**保真度由复用 Chromium 内核天然保证**，本模块只负责资源供给与生命周期管理；不做滚动同步（编辑面与渲染面合一后无同步对象，2026-09-22 退役）。
- **关键约束**：预览运行在沙箱 iframe 中，通过自定义协议 `vfs://` 从主进程拉取 VFS 资源；预览页无 Node 权限、无法访问真实文件系统，仅能触达当前文档所在 VFS 子树。

### M5 编辑器模块

- **职责**（2026-09-22 修订）：**HTML 文档的所见即所得编辑**——在渲染面上直接编辑，仅支持既有元素的内容级简单修改；删除元素保存后即永久移除；不提供标签样式设计能力。CSS/JS/纯文本的源码编辑（语法高亮、括号匹配、自动缩进、查找替换）；编辑状态与 VFS 写操作的联动（保存/自动保存）。
- **边界**：不做 HTML 源码编辑视图（用户决策：预览与源码修改不分开）；所见即所得撤销采用渲染面会话内原生撤销，不提供跨重启撤销；不做格式化引擎集成（P2 预留 Prettier）。

### M6 模糊搜索模块

- **职责**：对文件名与文本内容建立全文索引（SQLite FTS5 trigram）；提供子串模糊匹配、多关键词、按类型/目录过滤；结果高亮与定位跳转；索引随 VFS 写操作实时增量更新。
- **边界**：不做语义搜索、不做正则搜索（P2 预留）；拼音模糊检索为 P2 扩展项。
- **关键约束**：万级文档规模下搜索 P95 ≤ 200ms（见 03 号文档性能指标）；索引与内容必须同事务更新，禁止出现"搜到已删除内容"的不一致窗口。

### M7 导入导出模块

- **职责**：从真实磁盘目录批量导入文件/文件夹进 VFS（保持目录结构）；将 VFS 子树导出为真实目录；导出时将 HTML 内的 `vfs://` 引用改写为相对路径，保证导出后双击即可在浏览器打开。
- **边界**：不做双向实时同步，导入/导出是一次性拷贝动作。

### M8 辅助功能模块

- **职责**：
  - **回收站**：软删除节点的列表、还原、彻底清除、一键清空；
  - **最近打开**：最近编辑文档列表与快速恢复工作区；
  - **设置**：主题、编辑器字号、自动保存间隔、去抖时长、**数据目录查看、更改与迁移**（2026-09-22 修订，原「数据库位置查看」）、手动备份；
  - **自动备份**：每日滚动备份（保留最近 N 份）。
- **边界**：均为既有模块能力的界面化与策略化组合，不引入新的存储模型（备份即数据库文件快照）。

## 4. 统一建模语言与约定

- 优先级定义：**P0** = MVP 必须；**P1** = 首个正式版应具备；**P2** = 后续迭代/预留。
- "基础功能"清单（用户原话"模糊搜索等基础功能"所覆盖的最小集合）：新建/重命名/移动/删除文件与文件夹、打开与编辑、实时预览、模糊搜索、导入导出、回收站。
- 明确的**非目标**（当前版本不做）：云同步、多设备协同、多人协作、移动端、插件系统、自研排版引擎、版本历史（回收站兜底，版本历史列为 P2 预留）。
