### 1.3 择定结论与对技能产出的裁剪（不是照单全收）

**择候选 A「冷静专业工具风」轴**：低饱和冷灰（slate）中性色、紧凑密度、直线小圆角（基准 4px）、克制动效。三处有意裁剪并留证：

1. **否决「仅暗色」倾向**：技能输出 A 明示 light not-recommended，但本项目需求为 light/dark 双主题强制（brief Interfaces），技能建议让位于项目约束——落法为 A 轴冷灰在 light/dark 各出一套语义变量（见 §三）。
2. **否决网络字体**（JetBrains Mono / IBM Plex Sans / Nunito Sans 均不采纳）：桌面工具零网络依赖，主文档 CSP `default-src 'self'` 无字体下载面，UI 字体栈沿用系统栈（brief Step 2 明确）。
3. **否决绿 accent**：全站当前无品牌强调色诉求，accent 语义收敛为「悬停表面」（shadcn 惯例），避免引入无业务承载的彩色焦点。

## 二、布局语言

- **三栏工作台布局**：应用壳 = 纵向 flex（标题栏 auto / 工作台行 1fr / 状态栏 auto）；工作台行为**横向 flex**（活动栏 | 侧栏 | 侧栏分隔条 | 画布区），侧栏宽度经内联 `width: N%` 注入、折叠态为 48px 窄条（`w-12`），分隔条为 4px 实体轨（`bg-border`，可拖拽者 `cursor-col-resize` + hover 提示）。**（M6 起为 flex 行而非 grid——M5 遗留描述「三栏区为 grid，列模板由 Workspace 内联注入」已作废；该事实正是 M8 折叠宽度过渡成立的依据，见 §十一）**
- **间距标尺（4 的倍数）**：一律使用 Tailwind spacing **整数步进**（1 步 = 4px，合法取值即 p-1/p-2/p-3/p-4… → 4/8/12/16…px）；**禁半步**（`x.5` 步进产生 6/10px 离尺值）与 3/5/7px 等非 4 倍数离尺值——判定规则机械：间距值必须能被 4 整除。面板内边距 8px（p-2）/12px（p-3）；工具栏与列表缝隙 4px（gap-1）；浮层内边距 16px（p-4）。
- **信息层级**：一级=面板标题栏（12px，muted 中性）；二级=内容主体（树节点/标签 12–14px）；三级=辅助信息（状态文案、占位态 12px muted-foreground）。层级只经「字号 + 颜色」表达，不加粗除激活态外的正文。
- **壳高**：应用壳占满视口（`h-screen`），面板内部滚动（树列表 `overflow-auto`），页面级不滚动。

## 四、字体阶梯

- **UI 字体栈（`--font-sans`，沿用系统栈）**：`system-ui, -apple-system, 'Segoe UI', 'Microsoft YaHei', sans-serif`——中文Windows 回落微软雅黑，macOS 走系统中文栈；不引入任何网络字体（§1.3-2）。
- **等宽栈（`--font-mono`，仅文档备案）**：`ui-monospace, 'Cascadia Mono', 'Segoe UI Mono', Menlo, Consolas, monospace`。CodeMirror 编辑区沿用 CM 自带等宽栈，本系统不覆盖（避免动编辑器内部度量）。
- **字号阶梯（固定三档，禁止体外值）**：

| 档 | 值 | 工具类 | 用途 |
| --- | --- | --- | --- |
| chrome | 12px | `text-xs` | 标题栏/工具栏/标签页/状态栏/toast |
| content | 14px | `text-sm` | 树节点、空态占位正文 |
| display | 16px | `text-base` | 预留（首启引导等未来场景） |

- **行高**：chrome 面 `leading-5`（20px，配 12px 字号）；内容面正文 1.5（`leading-normal`）。标签行、树行单行截断（`truncate`），禁换行撑高。

## 五、圆角 / 阴影 / 边框标尺

- **圆角（基准 `--radius: 0.25rem` = 4px，shadcn calc 派生）**：

| token | 值 | 用途 |
| --- | --- | --- |
| `rounded-sm` = `calc(var(--radius) - 2px)` | 2px | 树节点/标签/小图标钮 |
| `rounded-md` = `var(--radius)` | 4px | 工具钮、toast、输入框 |
| `rounded-lg` = `calc(var(--radius) + 4px)` | 8px | 浮层卡片（重命名浮层） |

- **阴影**：仅浮层允许投影（toast / 重命名浮层 `shadow-md`）；面板与内容区零阴影——空间分隔只由 1px 边框与分隔条承担（冷静工具风，拒绝装饰性投影）。
- **边框**：统一 1px `border-border`；三栏分隔为 4px 实体轨（`bg-border`）而非 1px 线——宽度即拖拽命中面（E2E `.lt-divider-*` 锚点依赖该轨存在）。

## 六、动效规范

### 6.1 tokens

| token | 值 | Tailwind 用法 | 用途 |
| --- | --- | --- | --- |
| instant | 100ms | `duration-100` | hover/焦点等即时反馈；面板/视图切换淡入 |
| fast | 180ms | `duration-180` | 内联表面过渡（侧栏折叠/展开宽度与内容淡变——M8 首个消费面） |
| normal | 240ms | `duration-240` | 浮层/toast/进度面板出入场 |
| 缓动·标准 | `ease-out`（cubic-bezier(0, 0, 0.2, 1)） | `ease-out` | 一切入场 |
| 缓动·出场 | `ease-in`（cubic-bezier(0.4, 0, 1, 1)） | `ease-in` | 出场：侧栏内容层折叠退场、toast/进度面板退场（M8 起已消费） |

（**M8 修订**：时长档位的唯一事实来源为**字面量工具类** `duration-100/180/240`；`theme.css` 原 `--duration-instant/fast/normal` 三条变量**已删除**——Tailwind v4 的 `duration` 工具读 `--transition-duration-*` 命名空间，原变量永不进构建产物、零消费面，属死配置（全局规范 §四 死代码零容忍）。同时 `theme.css` `@theme` 新增 `--default-transition-timing-function: cubic-bezier(0, 0, 0.2, 1)`，令全仓 `transition-*` 一次到位为 ease-out；**注意 `animate-in/out` 的动画简写读 `var(--tw-ease, ease)`、不读该键**，故浮层/面板的入场仍须在消费点显式写 `ease-out`、出场写 `ease-in`。）

### 6.2 何物可动 / 何物不可动（红线）

**可动**：浮层与 toast 的出入场（fade + 轻位移/缩放）；**侧栏折叠/展开过渡**（M8 落地：单元素 `transition-[width]` 180ms + 内容层 180ms 淡变；拖拽路径仍禁过渡，见下）；面板/视图切换淡入（100ms）；按钮按压微反馈（按下即时、释放平滑，见下）；hover 与焦点反馈（背景/颜色 100ms）。

**不可动**：
- 文本编辑一切路径——CM6 编辑区不叠加 UI 级过渡/动画（编辑器自身动画由库管理，外壳不得注入）；
- 滚动跟随与滚动位置恢复（`scrollDOM.scrollTop` 直写，无平滑滚动）；
- **拖拽直跟手**——分隔条 `pointermove` 路径禁任何 transition。M8 实现口径：拖拽期经 `data-dragging` 摘除侧栏宽度过渡 + 分隔条颜色固化在 hover 面 + 画布 `pointer-events-none`（指针越过 iframe 时光标才由壳层接管）+ `body.lt-col-dragging` 固化 `col-resize` 与禁选；
- **按钮按下必须即时**（零延迟反馈）：经 `active:duration-0` 实现——按下瞬间过渡时长为 0，释放后该声明失效、回到 `duration-100` 平滑回弹。按压形态两类，禁混用：**纯图标钮**（前景 `--muted-foreground`）走 `active:scale-95`（因其前景色在按压面上仅 3.41/4.04，不达对比门槛）；**含文字钮**走表面深一档（`--accent-active` / `primary` 80%）。**禁行级元素按压态**（树行/标签/列表行——宽行缩放即抖动，且行点击结果由选中态自证）。

### 6.3 `prefers-reduced-motion` 降级策略

`theme.css` 基线层全局降级：reduce 用户的动画/过渡时长压至 0.01ms、迭代次数 1——等效「全部动效瞬时完成」，布局与信息呈现零损失。该降级为宪法级兜底，新增动画不得绕过（不使用 inline style 注入动画时长）。

### 6.4 本批次动效交付范围

**M5 批次**：toast 入场（fade + slide-in-from-bottom，240ms）；hover/焦点过渡（100ms）。
**M8 批次（2026-09-23，用户实测反馈「侧边栏收起/界面加载跳转/按钮操作/拖拽加过渡与微交互」）已交付**：①侧栏折叠/展开宽度过渡（180ms，单元素常驻 + 内容层退场存在性）；②侧栏面板切换淡入 100ms + 设置页入场 100ms（重建 M6 丢失项）；③按钮按压微交互（两档形态，见 §6.2）；④分隔条拖拽三态（hover/拖拽中/释放）；⑤toast 退场 240ms（§6.4 与 §九-8 挂账项结清）；⑥动效基建修复（死 token 删除、全局缓动基线）。完整清单、裁决推翻依据与实测数据见 **§十一**。

### 7.2 自研组件 Tailwind 形态规范（标准类串，禁体外发挥）

以下类串为各组件的**唯一规范形态**；`lt-*` 语义类名保留为**测试锚点与结构语义**（E2E/单测依赖，见 §7.3），视觉一律由 Tailwind 工具类承载，**禁止再向 `lt-*` 写声明式 CSS**。

## 九、打磨增量（M5 批次⑧ Task 15，taste-skill 双技能驱动）

> 本章记录打磨批次对基线语言的**增量修正与新增惯例**（审计发现基线可改进处，先回写本档再落码）；未列出的既有规范不变。打磨对照表（generic AI 味清单 → 逐项处置）见 `.superpowers/sdd/2026-09-19-M5-导入导出与辅助功能/polish-checklist.md`。

1. **`--destructive` 双主题各调一档（对比度缺口修复）**：审计发现破坏色文本的真正最坏表面是**悬停 accent 面**（标签 dirty 标记、下拉项 hover），原取值在该面不达正文门槛——light `#DC2626`/`#E2E8F0` 实算 3.92:1、dark `#EF4444`/`#1E293B` 实算 3.89:1（原 §3.1 只验了 background 面，属基线验算缺口）。修正为 light `#B91C1C`（red-700，accent 面实算 5.25:1）、dark `#F87171`（red-400，accent 面实算 5.29:1）；全组合重算见 §3.1 表 #9/#10/#16/#17 与新增 #18/#19，均较原值提升。`--destructive-foreground` 配对不变（dark 深字白字裁决照旧：白字对 #F87171 仅 2.77:1）。
2. **键盘焦点环基线（`button:focus-visible`）**：自研钮类（工具钮/树行/标签/「⋯」触发钮/关闭钮）原先仅 UA auto 轮廓叠加 50% 透明 ring 色，弱且与输入框的 2px ring 形态不一致；`theme.css` base 层新增 `button:focus-visible { outline: 2px solid var(--ring) }` 全站统一（shadcn 组件自带 focus-visible 样式在 utilities 层、级联优先不受影响）。ring 色非文本对比度 light 4.55 / dark 6.96（≥3:1）。新增交互钮如自带 ring 形态可不依赖本兜底，但不得写明暗条件色。
3. **shadcn 浮层消费侧覆写惯例**：radix 模板默认形态与本章标尺冲突处，经消费侧 `className` 覆写（cn/tailwind-merge「外部类覆盖内部类」合法场景，不改写 `components/ui/` 源码）：浮层内边距对齐 16px（`AlertDialogContent` 追加 `p-4` 覆写模板 `p-6`）；标题对齐字号三档 display 16px（`AlertDialogTitle` 追加 `text-base` 覆写模板 `text-lg` 18px 体外值）。后续 `shadcn add` 的组件消费同此惯例。
4. **数据数字 `tabular-nums` 惯例**：同屏随操作刷新的数字（进度计数、命中计数、时间戳、滑块值回显、备份大小）统一加 `tabular-nums`——比例数字逐帧刷新时宽度抖动是廉价感来源；静态标签文字不用。
5. **组合空态惯例**：面板级空态占位（编辑器/预览「未选中文件」「文档不可用」）由裸文字升级为「装饰性图标（aria-hidden，1.5 描边、60% 不透明度、24px）+ 原文案」纵向组合，`gap-2`；**文案与 `lt-*` 锚点零变更**（svg 不产生 textContent）。列表内空态（搜索/回收站）维持裸文字——占位面积小，加图标反而喧宾。
6. **树行「⋯」触发钮显形策略**：常态 `opacity-0`，行悬停（`group-hover`）/ 行内焦点（`group-focus-within`）/ 菜单展开（radix `data-[state=open]`）三态显形——每行常驻 20px 钮是恒定噪音；透明态仍占位且可命中，纯呈现零行为变化。列表行内「hover 显形」控件一律照此三态齐全，禁只挂 hover（键盘用户焦点不可达）。

## 十二、画布文档面基底保真修复（2026-09-23）

用户实测反馈「有时候 html 文件渲染会出现莫名其妙的灰色遮罩层」的核验与修复（四项历史前置修复项批次；完整证据链见 `docs/progress/2026-09-23-四项历史前置修复项核验报告.md`）。

**第一步先证伪「遮罩层」假设**：画布区 16 点 `elementsFromPoint` 网格采样，最上层元素恒为 `IFRAME`——不存在任何覆盖文档的应用层元素（含 `pointer-events-none` 浮层与定位浮层），故现象不在应用 DOM 层。

**真因**：Chromium 中子文档根元素背景为 `transparent` 时，其画布**对嵌入者透明**；文档自身未设 `background`（纯结构 HTML、外链 CSS 被 CSP 拦掉、导出文档仅内联正文等）时，最近的应用底色即透过文档显示。单变量实验（候选位置逐一改醒目色，每次改动后等待重绘再复采——首次实测因合成器缓存出现自相矛盾读数，加 400ms 等待后读数自洽）**四处任一改色文档区即变该色**（iframe 元素 / `.lt-html-canvas` 容器 / `section.lt-canvas` / 文档 `html`），文档面无自身基底由此成为可核证事实：

| 状态 | 亮色主题文档区主色 | 暗色主题文档区主色 |
| --- | --- | --- |
| 修复前 | `#f8fafc`（= 应用 `--background`） | `#0f172a`（= 应用暗色 `--background`） |
| 修复后 | `#ffffff` | `#ffffff` |

**裁决：文档面基底取浏览器白，由 iframe 元素自身承载**（`.lt-canvas-frame` 加 `bg-white`）。

- **为何是白**：浏览器对顶层文档恒以白色为画布基底（未改 `color-scheme` 时的默认画布），而产品红线是「实时预览与浏览器渲染完全一致」（docs/03 一致性红线、FR-RENDER-01）。故暗色主题下文档面亦为白，与浏览器同；文档自设背景时基底恒被覆盖（紫底反证实测：文档设 `#800080` 后文档区主色 `128,0,128`）。
- **为何落 iframe 而不落文档内**：不触碰用户文档（保存序列化经 `data-lt-injected` 剥离，注入式方案还会与用户自身 `html` 背景规则争优先级），亦不违反 §九「不注入任何 UA 样式（保真红线）」——白就是浏览器的默认画布，保真度只增不减。
- **已知边界（不在本修复范围）**：CSP `default-src 'self'` 会拦掉文档引用的外链样式表（B.5-3 安全红线不可放宽），此类文档在应用内呈「未套样式 + 白底」、在浏览器内呈「套样式」——样式缺失是安全基线的既定代价，本修复保证的是「基底与浏览器一致」，不承诺「外链资源可用」。

**测试锚点增量**：单测 `html-canvas`「画布 iframe 携带浏览器白底」（jsdom 不加载 Tailwind 产物，断言契约类名）；E2E `preview.spec`「画布文档面基底为浏览器白」（真机 `getComputedStyle` 断言 `rgb(255, 255, 255)`）。两处守卫均做**鉴别力验证**（临时移除 `bg-white` 断言即红）；`bg-white` 规则生成经构建产物 grep 核证（`.bg-white{background-color:var(--color-white)}`）。

## 十三、弹窗统一与行操作入口可见化（M8 用户实测反馈批次，2026-09-23）

用户实测反馈「弹窗需要优化样式设计」「新建目录后完全无法操作、操作键都没有」两项的处置（M5 打磨对照表 #13 挂账项的立项落地）。

### 13.1 原生弹窗 → 应用内确认弹窗（`ConfirmDialog`）

**问题**：4 处不可逆/带参操作此前走原生 `window.confirm`——OS 皮肤与应用设计语言脱节（亮暗主题、圆角、按钮纪律全部由 OS 决定），且与站内已有的应用内浮层（导入确认、数据迁移、重命名）形态分裂。

**落法**：新建 `features/ui/ConfirmDialog.tsx`，**零新视觉语言**——复用既有 `AlertDialog` 原语（radix：焦点陷阱、Esc/遮罩关闭、`role="alertdialog"`）+ 设计系统标尺（内边距 p-4、标题 text-base、操作钮 h-8 text-xs、出入场 duration-240）；破坏性操作确认钮走破坏色（与工具钮构成色彩分级族），非破坏性（大文件打开）走主色；**取消项由 radix AlertDialog 默认聚焦**（破坏性操作的安全默认：回车不误触不可逆动作）。

| 站点 | 标题 | 描述文案（逐字沿用原 confirm 文案） | 分级 |
| --- | --- | --- | --- |
| 回收站 · 彻底删除 | 彻底删除 | `彻底删除「<名>」？不可恢复` | 破坏色 |
| 回收站 · 清空 | 清空回收站 | `将彻底删除 N 个节点，不可恢复` | 破坏色 |
| 打开 5–50MB 大文件 | 打开大文件 | `大文件打开可能卡顿，是否继续？` | 主色 |
| 关窗 unsaved-guard | 退出应用 | `有未保存的更改，确定退出？` | 破坏色 |

**推翻「不做」裁决并留证**（M5 打磨对照表 #13、M4 spec D3）：原不做理由有二——①「换应用内对话框属行为面新增」；②「M4 裁决 confirm 为 Playwright 可驱动的既定选型」。②被反向满足：应用内浮层由 DOM 直接驱动，**可驱动性更强**（E2E 现在能验收「取消不放行 / 确认放行」两个分支，原生框时代只能验收确认分支）；①由用户实测反馈立项（用户诉求优先于打磨边界）。文案逐字沿用使语义锚零漂移。

**实现纪律**：`ConfirmDialog` 内以 `confirmedRef` 记录「确认已按」——radix 在 Action 点击后同样触发 `onOpenChange(false)`，无守卫会把「确认」二次上报为「取消」（消费侧多为 Promise 兑现器或不可逆动作入口，双报污染语义）；组件契约用例锁死该语义并做鉴别力验证。Workspace 侧确认请求经 `askConfirm` **Promise 化**（`await` 语义与原生同步读值等价，分支结构零改动）。

### 13.2 行操作入口常态可见（推翻 M5「仅悬停显形」降噪裁决）

**问题**：树行「⋯」触发钮原为 `opacity-0` + 悬停/焦点/菜单展开三态显形（M5 打磨降噪：每行常驻 20px 钮是恒定视觉噪音）。用户实测反馈「新建目录后完全无法操作、操作键都没有」——行级操作入口在静止态不可见，发现性代价高于降噪收益。

**落法**：常态可见，前景取 `text-muted-foreground`（与 chevron/类型图标同档，对比度达标；不取低透明度——半透明前景在行底色上不达非文本对比门槛），悬停/焦点/菜单展开经表面（`bg-accent`）与前景提亮表达可交互。与工具栏图标钮「常态可见」的既有口径统一。

### 14.2 基建与关键实测

- **编辑目标高亮色 `#64748B`（唯一硬编码字面例外）**：沙箱子文档 opaque origin 读不到宿主 CSS 变量且文档底色不可预知——取 light 档 `--ring` 现值（白底 4.9:1 / `#0F172A` 底 3.4:1 双达标；dark 档 `#94A3B8` 对白底 2.56:1 不达标，故**刻意不随主题**）；同源注释落在 `theme.css` `--ring` 与桥内两处（防漂移）。
- **序列化记账还原（蓝图 §1.4 必修项）**：桥写过的 `contenteditable`/`spellcheck` 以 (元素, 属性, 原值) 三元组记账（`data-lt-touched` 按文档序对位克隆树还原）——原值存在还原原值、不存在才移除；用户文档自带的 contentEditable 区域不得被误删（无条件 removeAttribute 会静默改用户文档）。桥自有标记（`data-lt-hover`/`data-lt-active`/`data-lt-editing`/注入 style）无条件剥离。
- **首装/导航竞态（真机 E2E 实证）**：开签后立即点「编辑」与首帧 onLoad 竞态——首装曾误清编辑意图且 enter 消息落入未装桥文档被丢弃；修正=onLoad 以 loadedIds 实时镜像判定首装（保留意图，装载门放行后补发 enter）/导航（注销编辑，不跨导航存活），enter 下发加装载门。
- **闸门命中表（施工修订并留证）**：编辑态 click 直接命中目标判定——表单控件/媒体/嵌入物/注入物/html 根=退出编辑；body 与文本元素=合法目标（body 为蓝图 A.5 键盘落笔目标，点击 body 不得退出）。**SKIP 表需含 BUTTON/IMG/VIDEO/AUDIO/CANVAS 等**且判定走 `tagName.toUpperCase()` 归一（SVG 内嵌元素 tagName 保留小写，`SKIP['svg']` 永不命中——探针实证「点按钮不退出」根因即此）。媒体元素删除能力随「媒体命中=退出」边界移除，FR-EDIT-05 的「删除元素」收敛为编辑目标子树内的内容级删除（docs/03 已同步）。
- **Electron 44 剪贴板同步 API 移除（运行时实证）**：`clipboard.readBuffer`/`availableFormats` 等同步面运行时为 undefined，唯一入口为异步 `clipboard.read(): Promise<ClipboardItem[]>`，文件复制统一映射 `text/uri-list`；粘贴导入生产路径=主进程异步读清单直导（路径不出主进程，不经对话框登记簿——登记簿信任边界针对渲染层可伪造串，本通道不接收路径）。真机 E2E 经 PowerShell `Set-Clipboard`（真实 FileDropList）驱动全链路。
- **构建产物核证（M7 教训守卫）**：`aria-pressed:` 变体、`data-[drop-target=true]:*`、`data-[phase=drop]:transition-transform`、`duration-180`、`zoom-*`、`slide-in-from-top-1` 均已在 `dist/renderer/assets/*.css` 生成规则。
