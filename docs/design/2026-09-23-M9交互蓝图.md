## 一、总览

### 1.1 四面定位（一句话）

| 面 | 定位 | 核心矛盾与解法 |
| --- | --- | --- |
| A · HTML 画布双态 | 默认**交互态**（整页与原浏览器一致：脚本/按钮/表单/链接可用），经工具条「编辑」钮或双击文本元素进入**编辑态**，只对选中元素就地开编辑 | 保真 vs 可改：编辑态的一切注入（contentEditable、高亮样式、事件闸门）都必须可逆且**序列化剥净** |
| B · 树空白区与路径条 | 空白区点击＝清除树内选中覆盖（新建/导入落点回落根）；路径条升为「根目录」可点选入口 | 根无行可点 vs 落点可见性：以路径条这一**唯一根入口**承担选中、pick 目标与拖拽落点三职责 |
| C · 拖拽移动 + 幽灵 | pointer 事件自制拖拽（非 HTML5 DnD）：48px 正方形幽灵零延迟跟随，落点三态反馈，成功/取消两路收场 | 手势可控 vs 纪律：跟随路径零过渡，落点反馈复用既有 pick-target 视觉语言，不发明第二套 |
| D · 更新入口 | 标题栏 chip 只在「有可更新版本」后出现（可用/下载中/待重启三态），设置页「关于」承载版本与手动检查 | 待办可见 vs 克制：无新版本时标题栏零存在感；失败与不支持只在设置页以 muted 说明 |

### 1.2 与既有设计语言的关系（只消费，不发明）

- **色彩**：新元素只用语义 token（`bg-popover` / `border-border` / `text-popover-foreground` / `bg-primary` / `ring-ring` / `bg-accent` / `bg-accent-active` / `bg-destructive/10` / `ring-destructive`）；类型色沿用树行既有双档（amber/orange/emerald/violet/sky）。零新 token、零硬编码（唯一例外：文档内注入高亮色，见 A.2-3，理由与同源关系已列明）。
- **几何与动效**：4px 标尺整数步进（24/28/32/40/48px）；圆角沿用 `rounded-sm`(2px 行/钮) / `rounded-md`(4px toast、浮层内控件) / `rounded-lg`(8px 浮层卡片、拖拽幽灵)；投影仍只给浮层；只用 `transform` / `opacity` / `color`，时长三档 100/180/240ms，退场一律 `fill-mode-forwards`。
- **组件形态**：树行、工具钮、图标钮类串沿用 `features/ui/classStrings.ts` 与设计系统 §7.2；本批只对树行类串做**追加式**增量（落点/非法变体，见 C.3），须同步回写设计系统 §7.2。

## 二、面 A · HTML 画布「交互 / 编辑」双态

### A.1 状态机

```text
交互态（默认，加载即此态）：文档脚本/表单/链接/媒体全部可用；桥不写任何属性与样式（零注入）
 ├─ 工具条「编辑」钮（aria-pressed=false）────▶ 编辑态（工具条入口：进入后点选元素就地编辑）
 └─ 双击文本元素（桥内判定合格）────────────▶ 编辑态（目标＝该元素，光标落至点击点）
编辑态（画布级单值 editingNodeId：同一时刻至多一篇文档在编辑态）
 ├─ 单击可编辑文本元素 → 切换目标（旧目标还原属性，新目标 contentEditable）
 ├─ 单击非文本区域/空白/媒体/表单控件 → 退出（还原纯交互）
 ├─ Esc（桥内判定，焦点在文档内）／工具条「编辑」钮／切签（对旧文档发 exit）→ 退出
 ├─ 画布重载 / 标签关闭 → 退出（编辑目标不跨导航存活）
 └─ 输入 → 桥逐输入序列化 lt:doc-edit → 既有保存管线（语义零变更）
```

- 编辑态**不产生脏态**；只有真实输入才经既有管线置脏（重载钮禁用语义逐字不变）。
- 状态形态采用在途的**画布级单值**（非按标签 Map）：切签即对旧文档收口，不存在「后台文档脚本仍被冻结」的隐藏态（§1.4）。

### A.2 几何与视觉规格

1. **画布工具角（右下角纵排）**：既有「从库重新加载」钮上移，编辑钮置顶，`gap-2`（8px），两钮同规格 32px 圆钮。
   - 容器 `.lt-canvas-toolbar`：`absolute right-4 bottom-4 flex flex-col items-center gap-2 pointer-events-none`（容器透明区与两钮间 8px 缝隙不吞文档点击，钮各自 `pointer-events-auto`——在途缺此项，须补，见 §1.4）。
   - 编辑钮 `.lt-canvas-edit-toggle`：`pointer-events-auto inline-flex h-8 w-8 items-center justify-center rounded-full border shadow-md transition-[color,background-color,scale] duration-100 active:duration-0 active:scale-95` + 态条件类（交互态 `border-border bg-popover text-popover-foreground hover:bg-accent hover:text-accent-foreground`；编辑态 `border-primary bg-primary text-primary-foreground` + 图标换 `X`——在途形态，采纳）；`aria-label="编辑"` **恒常**、`aria-pressed` 承载态（**不随态改名**，见 §1.4），`title` 随态：交互态「编辑文档内容（脚本与链接将暂停）」/ 编辑态「退出编辑（Esc）」。
   - 重载钮：既有类串 + `pointer-events-auto`（其余逐字不变，含 `aria-label="从库重新加载"` 与脏态禁用）；无激活标签时两钮同禁用（编辑钮 `disabled={activeId === null}`）。
2. **编辑态提示条** `.lt-canvas-edit-banner`（画布顶部居中浮动，**不改 iframe 尺寸**——整条下压会让文档重排，违保真红线）：`pointer-events-none absolute left-1/2 top-2 z-10 -translate-x-1/2 rounded-md border border-border bg-popover px-2 py-1 text-xs text-popover-foreground shadow-md`，文案逐字：`编辑中 · 脚本与链接已暂停 · Esc 退出`，`role="status"`。
3. **选中元素高亮（文档内绘制）**：桥在编辑态注入 `<style data-lt-injected="1">`，规则形如 `[data-lt-hover]{outline:1px dashed <色60%>}[data-lt-active]{outline:2px solid <色>}`（在途已落地该双属性形态，本文采纳），并由桥在候选/目标元素上挂 `data-lt-hover` / `data-lt-active`。
   - 为何 `outline`：不参与布局（零重排＝零保真代价）、不被文档盒模型样式覆盖、与全站焦点环规格同形（`2px solid` + offset，技能检索 Focus Appearance 条：≥2px 周长、3:1 对比）；高亮**无过渡**（瞬时）——位置指示不得滞后于点击，且 outline 无合成器动画路径。
   - **色值例外（唯一硬编码字面）**：取 **`#64748B`**（＝ light 档 `--ring` 现值，禁 `#3b82f6` 等体外色，见 §1.4）。理由：子文档无 token 上下文，且文档底色不可预知——`#64748B` 对白底 4.9:1、对 `#0F172A` 3.4:1 **双底达标**；dark 档 `--ring`（#94A3B8）对白底仅 2.56:1 不达标，故**不随主题切换**。同源关系在 `theme.css` 注释记录（防两侧漂移）。已知边界：文档底色恰为该色时高亮不可见（真实文档罕见）。

### A.3 注入桥协议与事件闸门

**消息扩展（postMessage，非 IPC 契约，不涉 docs/03）**：

| 方向 | 消息 | 载荷 | 说明 |
| --- | --- | --- | --- |
| 父→子 | `lt:edit-enter` | 无 | 进入编辑态（在途命名，见 §1.4）；桥置根元素 `data-lt-editing`、注入高亮样式、装载事件闸门 |
| 父→子 | `lt:edit-exit` | 无 | 还原属性 → 移除注入 style → 卸载闸门（顺序固定） |
| 子→父 | `lt:doc-edit` | `{ html }` | 既有，逐输入即报，语义零变更 |
| 子→父 | `lt:edit-state` | `{ editing }` | 桥内双击进入 / Esc 退出的状态回执（父窗工具条态同步；同值回写 bail-out 不成环） |

- 双击与 Esc **均在桥内判定**（父窗零 DOM 知识）：双击合格判定＝元素非 `input/textarea/select/button/img/video/audio/canvas/svg`、`textContent.trim() !== ''`、且非 `html/body`；未命中不干预（文档自身双击行为保留）。这也让 Esc 天然不与其他 Esc 消费者冲突（焦点不在文档内时桥不响应）。

**编辑态事件闸门**（桥内 `document` 上 capture 阶段注册，`lt:edit-exit` 时整组卸载）：

| 事件 | stopPropagation | preventDefault | 理由 |
| --- | --- | --- | --- |
| `click` / `dblclick` | ✔ | ✔ | 阻断文档自身 onclick/双击脚本、链接导航与表单控件默认动作（编辑期「脚本与链接暂停」的可判定实现） |
| `mousedown` / `mouseup` / `pointerdown` / `pointerup` | ✔ | ✘ | **不拦默认动作**：光标落点与选区是编辑本体（preventDefault 会毁掉 caret placement） |
| `submit` / `dragstart` | ✔ | ✔ | 表单不提交、禁止拖走文档内元素（不打断编辑会话） |
| `keydown` / `keyup` | ✔ | ✘ | 阻断文档自身快捷键脚本，保留键入默认行为 |

**序列化剥离（退出与每次上报共用同一 `ltSerialize`）**：① 移除全部 `[data-lt-injected]`（既有规则，自动覆盖新增的注入 `<style>`）；② 清除编辑痕迹——`data-lt-hover` / `data-lt-active`（在途命名）与根元素 `data-lt-editing` 无条件清除，而 `contenteditable` / `spellcheck` **必须记账还原**（以 `(元素, 属性, 原值)` 三元组记录，原值存在则还原原值、不存在才移除属性）：用户文档自带的 contentEditable 区域不得被误删，这是对在途「对所有元素无条件 removeAttribute」实现的必要修正（§1.4）；③ doctype 重建（既有，逐字保留）。

**导航闸门（数据一致性红线，必做）**：交互态下文档内的导航一律**不就地发生**——标签↔文档绑定与保存管线（`canvasDocsRef` 按 nodeId 记账）在就地导航后会错配。口径：① 站内 `vfs://` 目标 → 取消导航，渲染层经既有 `resolvePath` 命中则 `openFile`（开新标签，与树点选同入口）；② 站外 `http(s)` → 取消 + `shell.openExternal`（B.5-4 白名单）；③ 其余 scheme 与 `target=_blank`（`setWindowOpenHandler` 一律 deny，B.5-4）→ 取消并静默。主进程接线（`will-frame-navigate`）属实现类工作，登记 `TASK.md`；**最低可接受形态是「全部取消」**（点击无响应虽不理想，但不破坏一致性）。

### A.4 动效参数

| 元素 | 入场 | 退场 | 属性 |
| --- | --- | --- | --- |
| 编辑态提示条 | `duration-100 ease-out animate-in fade-in slide-in-from-top-1`（`translate` 独立属性，与 `-translate-x-1/2` 不冲突） | `duration-100 ease-in animate-out fade-out slide-out-to-top-1 fill-mode-forwards` | opacity + translate |
| 编辑目标高亮 | 无（瞬时） | 无（瞬时） | outline |
| 编辑钮按压 / pressed 态 | 按下 `active:duration-0`（既有纪律：按下即时、释放 100ms） | — | color / background / scale |

### A.5 键盘与 aria

- **键盘路径**：Tab → 编辑钮（`aria-label="编辑"`）→ Enter 进入编辑态 → 父窗 `iframe.contentWindow.focus()` **把键盘焦点交给文档**（编辑态的唯一目的是键入）；Esc（桥内判定）退出并把焦点**交还编辑钮**（焦点交接，M8 侧栏先例）。键盘用户不依赖「点选元素」：编辑态内无激活目标时以 body 为落笔目标（整页可编辑），双击/点选的元素级目标是指针便利路径——键盘能力不缩水（§1.4）。
- `aria-pressed` 表达开关态；提示条 `role="status"` 在进入编辑态时播报一次；**不**为编辑目标加 aria（跨文档边界的焦点/朗读由文档自身 contentEditable 语义承担）。

### A.7 边界与不做项

- 闸门**无法穷尽**脚本响应：`window` capture 阶段监听器、`setTimeout` / `requestAnimationFrame` 驱动的动画与轮播不受约束——列为已知边界（§八 R3），不做定时器劫持（改用户文档运行环境＝保真红线）。
- 不做：编辑态下的富文本工具条/格式命令（超本批边界，正文编辑能力以浏览器原生 contentEditable 为准）；编辑目标的父级/兄弟导航（上下键选择元素）；多元素同时编辑；编辑器与画布双向光标同步。

## 三、面 B · 树空白区失焦 + 路径条根目录入口

### B.1 状态机与语义

```text
树选中上下文 selectedTreeId = revealSelectionId ?? 激活标签节点（既有派生，不改）
 ├─ 空白区 pointerdown（左键，目标非交互元素，非 pick 模式）→ revealSelectionId = null（落点回落根）+ 树内焦点 blur
 ├─ 路径条点击 → revealSelectionId = ROOT_ID（显式把根选为当前目录）
 ├─ Esc（焦点在资源树 nav 内、未被 defaultPrevented）→ 同空白区清除（键盘等价）
 └─ pick 模式（move / 导入确认浮层）中：空白区与 Esc 一律 no-op，路径条＝根候选目标（既有 pick 语义）
```

### B.2 几何与视觉规格

1. **路径条（升为钮）** `.lt-tree-root-path`：`flex h-6 w-full shrink-0 min-w-0 items-center gap-1.5 border-b border-border px-2 text-left text-xs text-muted-foreground transition-colors duration-100 hover:bg-accent hover:text-accent-foreground aria-current:bg-accent aria-current:font-medium aria-current:text-accent-foreground data-[pick-target=true]:bg-primary/10 data-[pick-target=true]:ring-1 data-[pick-target=true]:ring-ring data-[drop-target=true]:bg-primary/10 data-[drop-target=true]:ring-1 data-[drop-target=true]:ring-ring`
   - 内容＝ `Folder`（`size-3.5 shrink-0 text-amber-500 dark:text-amber-400`，aria-hidden，与目录行同色）+ `<span className="truncate">{rootPath}</span>`（**可见文本仍只有路径**，`textContent` 断言不变）。
   - `aria-label={\`根目录：${rootPath}\`}`（可访问名含可见文本，满足 WCAG 2.5.3 Label in Name；同时告知语义）+ `title={rootPath}`；`aria-current={selectedTreeId === ROOT_ID ? 'true' : undefined}`（＝显式选中根时点亮，单一事实来源，不因「激活标签是文件而落点恰好为根」而误亮）；行高 24px（4px 标尺；指针命中下限），比树行（28px）矮一档＝次级信息位阶；`rootPath === null`（未装载）时不渲染（既有行为），此时根入口不可用，键盘路径为 Esc 清除。
2. **空白区**：顶层 `ul` 追加类名 `.lt-tree-list`（E2E 空白区锚，替代易断的 `nav > ul` 结构锚）。空白判定＝`pointerdown` 事件目标 `closest('button, input, a') === null`（含列表 8px 内边距、行间缝隙、末行下方留白）。
3. **反馈**：选中根时路径条点亮（`aria-current` 面）；hover 100ms 颜色过渡；无位移/无缩放（行级元素不加按压态，既有纪律）。

### B.3 键盘与 aria

- 路径条是原生 `<button>`：Tab 可达（树工具栏之后、列表之前）、Enter/Space 激活，焦点环走全站 `button:focus-visible` 基线（2px `--ring`）。
- Esc 清除选中：窗口 `keydown` 监听，条件「`event.target` 位于 `nav[aria-label="资源树"]` 内」且「`!event.defaultPrevented`」且「非 pick 模式」——菜单/浮层打开时焦点在 portal 内（不在 nav 内），天然不误触。

### B.4 动效

无新增动效：hover/aria-current 走 `transition-colors duration-100`；空白区清除与 Esc 清除瞬时（清除是「状态消失」，加动效只是延迟反馈）。

### B.5 测试锚点

- 新增：`.lt-tree-list`、路径条 `aria-label` 前缀「根目录：」（E2E 用 `getByRole('button', { name: /^根目录/ })`）、`data-pick-target` 在路径条上的复用（既有属性，新增承载元素）。
- 保持：`nav[aria-label="资源树"]`、`data-ready`、`.lt-tree-toolbar`、`.lt-tree-root-path`（类名保留，承载元素由 div 变 button）、行按钮 `aria-current` / `data-pick-target`、`li.lt-create-row`、`input[aria-label="新目录名称"]`、`.lt-move-bar` 全部逐字不变。

### B.6 边界与不做项

- 不做「已在此处」独立提示、路径条右键菜单（复制路径等）、面包屑分段（路径条不是导航栈，是本机数据目录的单值展示）；空白区不清空 pick 模式的目标（避免误改移动/导入目标）——刻意为之：pick 目标只由点选目录或点路径条改变。

## 四、面 C · 拖拽移动与幽灵

### C.1 状态机与手势

```text
pointerdown（行主按钮，button===0，非 pick 模式，非 ⋯ 触发钮/命名行输入）
 ├─ 位移 < 5px 抬起 → 交还原有点击语义（选中/开标签，零变更）
 └─ 位移 ≥ 5px（TREE_DRAG_THRESHOLD_PX=5，输入容差非布局间距）→ 进入拖拽
      ├─ 挂 body.lt-tree-dragging；渲染幽灵（入口 100ms）；源行 data-drag-source
      ├─ pointermove：幽灵跟随层直写 style.transform（**零 React 渲染**）；命中判定仅在目标变化时进 state
      ├─ 命中折叠目录持续 600ms（TREE_DRAG_EXPAND_DWELL_MS）→ 调既有 onToggle 展开（合法落点才计时）
      ├─ pointerup：合法 → onDropMove({sourceId, targetDirId}) → 收场 drop；非法/无目标 → 收场 cancel（零副作用）
      └─ pointercancel / Esc → 收场 cancel；Esc 需 preventDefault 阻断同刻其它 Esc 消费
```

- 收口清理（抬起与取消同路径，M8 分隔条先例）：摘 `body.lt-tree-dragging`、摘幽灵、清 dwell 计时器、清落点态。
- **点击抑制**：拖拽一旦越过阈值，置 `gestureRef.engaged = true`；每次 `pointerdown` 重置为 false；行主按钮 `onClick` 首行判 `if (gestureRef.engaged) return;`——防「取消拖拽落回源行」被当成一次点选/开签（经典缺陷点）。
- 行容器加 `onDragStart={(e) => e.preventDefault()}` 兜底原生文本拖拽；**不加** `select-none`（保留文件名可选中复制）。pick 模式（move / 导入）期间禁用拖拽（点选语义优先）；根无行不可拖（路径条只是落点）。

### C.2 幽灵几何与形态

- 两层结构（**必须分层**：跟随用 inline `transform`，动画层用 `animate-*` 的 keyframe `transform`，同元素会互相覆盖）：
  - 跟随层 `.lt-drag-ghost`：`pointer-events-none fixed left-0 top-0 z-50` + `style={{ transform: 'translate3d(x+8px, y+8px, 0)' }}`（左上角＝指针 + (8,8)，「提在手里」姿态；跟随路径**零 transition**）。
  - 动画层 `.lt-drag-ghost-card`：`flex size-12 items-center justify-center rounded-lg border border-border bg-popover shadow-md`，内含类型图标 `size-6` + `treeIconClassFor(meta)` 着色，图标形态＝**源行同形**（`treeIconFor(meta, isExpandedNode(node, expanded))`——「抓住的就是你看到的那个」）。
- **必须 portal 到 `document.body`**（`createPortal`）：树所在侧栏内容层带 `animate-in`（入场期会写 `transform` → `position: fixed` 后代在该窗口内改以动画层为包含块并落入 `overflow-hidden` 裁剪面；M8 已实测该陷阱，rename/import 浮层因此迁至工作台根层）。幽灵走 body portal，零依赖侧栏结构。
- 尺寸 48×48（4px 标尺，用户建议 44–56px 区间中值）；**不含名称**：48px 正方形内 12px 文本仅容 2–3 个全角字符，截断名是噪音；拖拽身份由「源行弱化 + 幽灵类型色 + 落点高亮」三段反馈共同表达（用户「可选名称」由此裁决为不做，见 §七）。

```text
┌ 侧栏 · 资源树 ─────────────────────────────┐
│ ▾ [目录] 笔记                     [⋯]      │
│     ▸ [目录] 2026                 [⋯]      │ ← 悬停 600ms 自动展开（折叠且合法）
│     [HTML] 索引.html              [⋯]      │
│ ▾ [目录] 素材                     [⋯]      │ ← data-drop-target=true（合法落点）
│       ┌──────────────┐                     │
│       │   [ 类型图标 ] │ ← .lt-drag-ghost   │
│       └──────────────┘   48×48 正方形       │
│        ↑ 左上角 = 指针 + (8, 8)             │
│ ▸ [目录] 2026                     [⋯]      │ ← data-drop-invalid=true（自身后代）
└────────────────────────────────────────────┘
```

### C.3 落点反馈（三态，复用既有视觉语言）

| 情形 | 属性 | 视觉（树行类串追加变体） | 说明 |
| --- | --- | --- | --- |
| 合法：目录，非自身/非后代/非当前父 | `data-drop-target="true"` | `data-[drop-target=true]:bg-primary/10 data-[drop-target=true]:ring-1 data-[drop-target=true]:ring-ring` | 与 `data-pick-target` **逐字节同形**（同一套「这是落点」语言，不发明第二套） |
| 非法：自身 / 自身后代 / 文件行 / **源当前父目录** | `data-drop-invalid="true"` | `data-[drop-invalid=true]:bg-destructive/10 data-[drop-invalid=true]:ring-1 data-[drop-invalid=true]:ring-destructive` | 同父归非法：`moveNode` 会撞同名约束（`E_VFS_DUPLICATE_NAME`），且「无动作」不该伪装成可放置；不给两套「不可」语言（中性态会被读成可放） |

- 无目标（列表空白 / 工具栏 / 画布区）：**无高亮**——反馈只落在候选落点行上，幽灵恒定不变色（身份不随位置改变）；「树外释放＝取消」由幽灵收场表达。
- 路径条（根目录）为合法落点，承载 `data-tree-node-id="1"` + 同套 `data-drop-target` 视觉——**面 B 与面 C 的复用点**。
- 对比度自证：`bg-destructive/10` 面 + `text-foreground` 文本仍为高对比（light ≈16:1 / dark ≈15:1）；`ring-destructive` 对 `--background` 为 6.18/6.45（非文本门槛 3:1）✓。
- 命中判定：`document.elementFromPoint(x, y)?.closest('[data-tree-node-id]')` → 读 `data-tree-node-type` + id；行容器新增 `data-tree-node-id` / `data-tree-node-type`（**不复用**既有 `button[data-node-id]`（⋯ 触发钮，E2E 与单测定位锚），避免 `querySelector('button[data-node-id=…]')` 命中歧义）。
- 自动展开：仅对**合法**目标目录、且处于折叠态时计时 600ms（展开走既有 `onToggle`，含懒加载拉取）；指针移开即清计时器；**不级联展开子级**；取消拖拽**不收回**已自动展开的目录（收起＝状态抖动，用户可能正想看里面）。

### C.4 动效参数

| 阶段 | 类串 / 手法 | 时长·缓动 | 属性 |
| --- | --- | --- | --- |
| 起拖入场（动画层） | `animate-in fade-in zoom-in-95 ease-out` | 100ms | opacity + scale |
| 跟随（跟随层） | inline `transform: translate3d(...)` 直写，**无任何 transition** | 0 | translate |
| 落下收场（合法） | 跟随层 `data-[phase=drop]:transition-[transform] data-[phase=drop]:duration-180 data-[phase=drop]:ease-out` → transform 指向目标行中心；动画层 `animate-out fade-out zoom-out-50 ease-in fill-mode-forwards` | 180ms | translate / scale + opacity |
| 取消收场 / 源行弱化 / 落点·非法高亮 | 动画层 `animate-out fade-out zoom-out-90 ease-in fill-mode-forwards`（原位）；行容器 `data-[drag-source=true]:opacity-40 transition-opacity duration-100`；行按钮既有 `transition-colors`（ring 瞬时出现） | 180 / 100ms | scale + opacity / color |

- 幽灵收场时长取 **180ms（fast 档）**而非浮层 240ms：它是指针直驱的临时表面（不承载交互内容、不进焦点管理），240ms 会读作「拖拽后卡顿」。两路收场都用 `fill-mode-forwards`：reduced-motion 全局把动画压到 0.01ms 时，`fill-mode:none` 会让幽灵闪回不透明并滞留一个退场时长（既有 toast/进度面板同款陷阱，已实测）。
- 幽灵摘除时机：收场动画播完（`GHOST_EXIT_MS = 180`）再卸载（沿用 `useExitPresence` 的「保快照播退场」形态），不做「先卸载再补动画」。

### C.5 全局接管态（`theme.css` base 层新增，紧邻 `body.lt-col-dragging`）

```css
body.lt-tree-dragging,
body.lt-tree-dragging * { cursor: grabbing !important; user-select: none !important; }
/* 画布穿透：拖拽期指针越过 iframe 时事件归属壳层（与侧栏分隔条同源纪律） */
body.lt-tree-dragging .lt-canvas { pointer-events: none; }
```

拖拽期指针可离开树、越过工具栏与画布：全局光标固化 + 禁选 + 画布 `pointer-events: none` 三者齐备，iframe 才收不到指针事件（§八 R1 仍需真机复核）。

### C.6 键盘与 aria（WCAG 2.2 SC 2.5.7 Dragging Movements）

- 拖拽**只是指针快捷路径**，等价路径既有且完整：行内「⋯」→「移动到…」（radix dropdown 自带方向键/Enter/Esc/焦点回落）与树工具栏「移动到…」→ 目录点选 → 「确认移动」。技能检索 Dragging Movements 条要求「不得让拖拽成为唯一方式」，本设计满足（无新增键盘拖拽实现——键盘拖拽属独立手势子系统，且现有等价路径覆盖同一任务）。
- 幽灵 `aria-hidden="true"`（纯视觉反馈，不进可访问树；无键盘拖拽＝播报无受益者）；行主按钮可访问名恒为节点名（**零 aria 变更**，既有测试锚点不受影响）；`draggable` 属性不使用（HTML5 DnD 已裁决不用，且会污染语义并触发原生拖拽）；不做拖拽过程的 `aria-live` 播报（会与既有 toast/进度面板播报争道）。

### C.7 测试锚点

- 新增：`.lt-drag-ghost`（跟随层，含 inline transform）/ `.lt-drag-ghost-card`（动画层）、`[data-tree-node-id]` / `[data-tree-node-type]`（行容器与路径条）、`[data-drag-source="true"]`、`[data-drop-target="true"]`、`[data-drop-invalid="true"]`、`body.lt-tree-dragging`、`data-[phase=drop|cancel]`（幽灵跟随层）。
- 保持：`button[data-node-id]`（⋯ 触发钮）、`aria-label="更多操作"`、行按钮 `aria-current`、`data-pick-target`、`.lt-move-bar` / `.lt-move-hint` / `aria-label="确认移动"|"取消移动"`、`[data-dragging=true]`（语义仍专指侧栏拖拽）。
- E2E 驱动形态（Playwright 确定性）：`page.mouse.move(start)` → `mouse.down()` → 分步 `mouse.move(...)`（≥5px）→ 断言 `.lt-drag-ghost` 存在且 `transform` 随指针变化 → `mouse.move(目标行)` → 断言 `[data-drop-target=true]` → `mouse.up()` → 断言树结构变更。

### C.8 边界与不做项

- 不做：边缘自动滚动（拖拽期 rAF 滚动循环是独立子系统，收益可由「先滚动/展开再拖」替代，列为后续候选）；跨窗口/跨应用拖拽（拖出应用即取消）；多选拖拽；同目录内排序（数据模型无排序字段，同父即非法落点）；拖拽到搜索/回收站面板；拖拽期间的拖尾/残影特效。

## 五、面 D · 更新入口

### 五.1 状态机与文案表（`UpdateState` 八态，docs/03 §7.1）

| 状态 | 标题栏 chip | 设置页「关于」状态行 | 设置页动作钮 |
| --- | --- | --- | --- |
| `idle` | 不渲染 | `尚未检查更新` | 「检查更新」 |
| `checking` | 不渲染（静默检查零存在感） | `正在检查更新…` | 禁用 |
| `up-to-date` | 不渲染 | `已是最新版本` | 「检查更新」 |
| `available` | **「更新到 v1.2.3」**（实心主色，`Download` 图标） | `发现新版本 v1.2.3` | 「下载」（与 chip 同一动作） |
| `downloading` | **「下载中 42%」**（中性 chip，`role="progressbar"`） | `正在下载 42%` | 禁用 |
| `downloaded` | **「重启以完成更新」**（实心主色，`RefreshCw` 图标） | `新版本已就绪，重启后生效` | 「重启并安装」 |
| `error` | 不渲染 | `检查更新失败，可稍后重试`（muted，非破坏色；`message` 非空时以 ` · ` 追加简短原因） | 「重试」 |
| `unsupported` | 不渲染 | 按 `reason` 映射：`dev` → `开发形态不支持应用内更新`；`platform` → `当前平台形态不支持应用内更新（未签名 macOS / 非 AppImage 的 Linux）` | 不渲染（无动作可做） |

- 静默检查（启动后一次 + 周期一次）不产生任何 UI，直到状态变为 `available`——**标题栏 chip 只在「有可更新版本」后存在**（用户指令原文的克制解读）。
- 「重启并安装」收口：先对全部脏标签执行既有 `saveController.flush(nodeId)` 冲刷 → 再走既有「退出应用」确认链（`ConfirmDialog`，脏态时才出现）→ 确认后 `update:install`。复用既有确认链，不新增弹窗语言。
- 失败与不支持一律 **muted 说明**而非破坏色：更新检查失败不影响使用（NFR-12），且主进程会周期重试——破坏色会把「自愈的暂时态」渲染成「用户犯了错」。

### 五.2 标题栏 chip 几何（`lt-titlebar` 内）

- 落位：右侧组（`lt-no-drag ml-auto flex items-center gap-2 self-stretch`）内、既有右侧留白占位**之前**；占位的 `ml-auto` 上移到该组（无 chip 时几何与现状逐像素等价）。菜单栏保持左对齐，chip 宽度随文案变化只移动自身左缘，**不挤动菜单**。
- **与 Windows 系统钮的间距**：win/linux 下该留白占位由 `w-24`（96px）扩为 `w-36`（144px ≥ Windows 三钮实测 138px），darwin 保持 `w-24`——否则 chip 右端会压进最小化钮命中区（§八 R6 待真机复核）。
- chip 两种形态：**可用 / 待重启态**（`<button className="lt-update-chip …">`）＝`inline-flex h-6 shrink-0 items-center gap-1 rounded-sm bg-primary px-2 text-xs text-primary-foreground transition-colors duration-100 hover:bg-primary/90 active:duration-0 active:bg-primary/80`，图标 `size-3.5`，`title` 可用态「下载新版本 v1.2.3」/ 待重启态「重启应用以完成更新」；**下载中态**（`<span role="progressbar" aria-valuenow={pct} aria-valuemin={0} aria-valuemax={100}>`）＝`inline-flex h-6 shrink-0 items-center gap-1 rounded-sm border border-border px-2 text-xs text-foreground tabular-nums`，文案 `下载中 {pct}%`。
- 视觉分级规则：**实心主色＝有待办动作**（可用/待重启），**中性＝进行中**（下载中，此刻用户无事可做）。进度只给百分比文本，不做 chip 内进度条（文本已完整表达进度且 `tabular-nums` 保证不抖动；24px 内 2px 进度条需 `scaleX` 技巧与新视觉语言，收益不抵复杂度，且与既有导入/导出进度面板「文本进度」口径一致）。状态切换**不重挂元素**（`key` 不随状态变）：文案/图标瞬时替换，表面色走 `transition-colors duration-100`。

### 五.3 设置页「关于」分区（导航第 6 项，图标 `Info`）

### 六.2 reduced-motion 降级汇总

- 全局兜底（`theme.css` base 层）已把 `animation-duration` / `transition-duration` 压至 0.01ms 且迭代 1——**本批所有新动效自动降级，无一处经 inline style 注入时长**（`transform` 直写只写位置、不写时长，不构成绕过）。
- **退场一律带 `fill-mode-forwards`**（幽灵两路收场、提示条退场）：否则 reduced-motion 下动画瞬时结束后回基础值，出现「幽灵闪回不透明并滞留一个退场时长」。
- **拖拽在 reduced-motion 下仍完全可用**：直接操纵不是装饰性动效（跟随本就是零过渡的指针镜像），仅入场/退场/弱化瞬时完成——不因降级削弱功能；编辑目标高亮、空白区清除选中、chip 状态切换本无动效，降级后呈现零损失。

## 七、明确不做（克制清单）

1. **幽灵内显示文件/目录名称**：48px 正方形内 12px 文本仅容 2–3 个全角字符，截断名比无名更噪音；身份由源行弱化 + 类型色 + 落点高亮承担。触发重估条件：真机实测「拖拽中认不出抓的是哪个」成为高频反馈时，改为 56px + 名称两行形态。
2. **边缘自动滚动 / 拖拽期 rAF 滚动循环**：独立手势子系统（速度曲线 + 与 dwell 展开的交互），收益可由「先滚动/展开再拖」替代。
3. **拖拽落点的「已在此处」中性态、同目录内排序**：同父归非法（不给第二套「不可」语言）；数据模型无排序字段（`updated_at` 非用户序），伪排序会让树顺序在不同刷新路径下漂移。
5. **编辑态富文本工具条 / 格式命令、编辑态定时器与动画的脚本冻结**：前者超本批边界（正文能力以浏览器原生 contentEditable 为准）；后者需劫持用户文档运行环境（保真红线），列为已知边界而非功能。
6. **面板级 hover 自动展开的级联展开**：单层 600ms 已覆盖绝大多数场景，级联会让树在拖拽中「自己动」。
7. **空白区与 Esc 在 pick 模式下的清除选中**：pick 目标只由显式点选改变，避免误改移动/导入落点。
8. **更新菜单项、重启后欢迎提示、更新日志、跳过版本、静默自动下载、下载取消**：见 §五.7 逐条理由。
9. **动态 `title` 表达画布模式**：稳定可访问名优先（可访问名抖动打断读屏上下文）。
10. **拖拽的 aria-live 播报、键盘拖拽实现、幽灵飞出屏幕外的收场动画**：无键盘拖拽＝播报无受益者（等价路径「移动到…」已覆盖同一任务，WCAG 2.5.7 达标）；树外释放即取消、原位收场（回飞会把注意力拉离落点且距离不可控）。
