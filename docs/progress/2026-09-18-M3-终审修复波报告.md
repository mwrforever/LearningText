## 二、304 探针证据（I-2 走降级路径）

指令预设降级触发条件为「Chromium 走 memory cache 零网络请求」；实测形态与预想**相反**——304 断言同样无法成立，按同条款精神降级并把实测行为勘误进 spec §4.2。

探针方法：Test 6 fill 终值保留 `<link rel="stylesheet" href="./a.css">`（a.css 自 Test 1 后从未变更），监听 `page.on('response')` 截取测试窗口内全部 vfs 响应，打印状态 / 请求 If-None-Match / 响应 ETag。

实测输出（`--retries=0` 连续 3 轮全量 preview spec，逐轮一致）：

```text
[probe] 200 a.html inm=none etag=W/"b93038…21"   ← fill 重载（主文档，内容已变）
[probe] 200 a.css  inm=none etag=W/"52c1358b2b2034e2f8b85968c9d4473f5a038fee3f5959d3a5edc63cbaef4a8c"
[probe] 200 a.html inm=none etag=W/"72704f…81"   ← 「！」重载（主文档，内容已变）
[probe] 200 a.css  inm=none etag=W/"52c1358b2b2034e2f8b85968c9d4473f5a038fee3f5959d3a5edc63cbaef4a8c"
```

- **常态形态（3/3 轮确定复现）**：两次重载对未变 a.css 均发起**无 If-None-Match 的 200 全量重取**——Chromium 对 `vfs://` 自定义 scheme 子资源跨 `location.replace` 重载不发起 no-cache 条件重验，缓存条目未被存储或未被咨询。
- **混现形态（修复波首次全量 E2E 跑 1 次）**：同流程实测到 `[304, 304, 200, 200]`——前两次重载带 If-None-Match 重验得 304，随后两次（rev 防撕裂追平触发的额外重载）又为无 INM 的 200。即 304 形态**非确定性行为**，不可作为 E2E 断言依赖。
- 降级后断言（实测恒真且不弱化既有覆盖）：未变子资源每轮重载均被重新请求（`cssRequests.length >= 2`，no-cache 不放行免验复用）+ 200 形态 css 响应 ETag 为 W/ 弱校验器形态且逐一相等（`Set.size === 1`，校验器跨重载稳定——304 收益的前提）。
- If-None-Match→304 传输语义不受影响，由集成测试锁死：`tests/integration/protocol/vfs-protocol.test.ts` 「ETag 命中 → 304 无体、未命中 → 200 正常体」。
- spec §4.2 已按指令以勘误块记入上述实测行为（含两形态、降级断言口径与证据出处）。
