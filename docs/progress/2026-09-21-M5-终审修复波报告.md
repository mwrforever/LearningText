# M5 终审修复报告（2026-09-21）

## Finding 1：io:import 入参登记簿校验对齐 export/openPath 既有口径

**问题**：`src/main/ipc.ts` 中 `io:export` 与 `shell:open-path` 两个 handler 均按 `dialogProducedDirs`（当次会话目录选择登记簿，由 `io:pick-directory` 在用户经 OS 对话框选择后登记）核对入参目录串，而 `ioImport` 直接把 `sourcePaths` 透传给导入服务，未做登记核对——三通道入参校验口径不一致，渲染层伪造串可直达磁盘读。

**前置核实（登记语义与核对粒度一致性）**：

- `src/main/app.ts`（225-236 行）：`pickDirectories` 经 `dialog.showOpenDialog`（openDirectory 模式）弹出，产出的每个 `result.filePaths` 原串登记入 `dialogProducedDirs`；
- 渲染层 Task 12 导入入口链（`src/renderer/src/features/workspace/Workspace.tsx` 735/742/763-764 行）：`window.api.pickDirectory({ multiple: true })` 返回值原样作为 `sourcePaths` 发起 `io:import` —— 对话框产出串与导入请求串逐字往返一致，精确串核对（`Set.has`）与登记语义一致，无需目录级归一。

**改动**：

1. `src/main/ipc.ts`：`ioImport` handler 对 `q.sourcePaths` 数组每一项执行 `deps.dialogProducedDirs.has(sourcePath)` 核对，任一未登记项抛 `AppError(E_IPC_BAD_PAYLOAD, '导入源路径必须来自目录选择对话框')`（与 export/openPath 两处同形态统一错误，整单拒绝、服务不发起）；`IpcHandlerDeps.dialogProducedDirs` 注释与 handler 域注释同步补齐「三通道同一信任边界」说明。
2. `src/shared/io-contract.ts`：`ImportRequestSchema` 契约注释补 sourcePaths 登记簿约束说明（防渲染层被攻破后任意路径读盘）。
3. `tests/unit/main/ipc.test.ts`：新增用例「io:import 登记簿内的源路径放行服务；登记外的串伪造拒绝（E_IPC_BAD_PAYLOAD）且服务不被调用」，形态照 `io:export` 既有用例——覆盖登记后正常导入、伪造串统一错误拒绝且服务不发起、多源清单混入单个未登记串整单拒绝三场景；既有 io:import 用例的源路径统一改为登记簿内 `D:/picked`（stub 登记簿默认含该串）。

## Finding 2：编辑器首建 view 无条件外观对齐——恢复单标签停留默认外观不自愈

**问题**：应用启动时「工作区恢复」还原上次标签（恢复式打开路径）的场景下，编辑器会话 state 由 Workspace 恢复链的 mount 闭包以装载完成前的默认外观值（light/14px）构造；之后设置装载完成、外观 props 更新为 dark/20 时，`EditorPanel` 换入 effect 的「无激活标签」分支只记账不派发重配，而首个 view 创建走「无需对齐」分支（旧注释假设 openFile 以当前外观构造 state）——结果：只恢复一个标签时外观 compartment 停留 light/14，整会话不自愈，直到用户手动切换主题/字号。

**改动**（commit `a23274a`）：

1. `src/renderer/src/features/editor/EditorPanel.tsx`：建视图分支（`view === null`）在 `new EditorView` 后无条件派发 `created.dispatch({ effects: appearanceReconfigureEffect(lastAppearanceRef.current) })`——CM6 compartment reconfigure 与当前值等值时为 no-op transaction，幂等安全；组件头注释与分支注释同步更新（「无需对齐」假设废止，恢复链 mount 闭包陈旧外观为已知例外）。
2. `tests/unit/renderer/editor-panel.test.tsx`：新增用例「恢复式打开：空态期外观变更已记账、会话持陈旧外观构造时，建视图分支仍对齐外观（终审回归）」——会话以陈旧外观（light/14）构造、空态挂载（activeTab=null，外观 props 已 dark/20 仅记账）、再激活恢复标签；断言 `EditorView.darkTheme` facet 翻转为 true（oneDark 以 `{dark:true}` 构造，facet 即 compartment 实际生效主题的可观察面）、doc 内容保留、`onDocChanged` 零调用（重配不误触发保存管线）。
