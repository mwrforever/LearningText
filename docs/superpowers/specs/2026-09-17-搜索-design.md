## 2. 现状基线与 v2 迁移（trigram 换表）

### 2.1 为什么必须 v2

M1 v1 实际建表为 `CREATE VIRTUAL TABLE node_fts USING fts5(name, body)`——**默认分词器 unicode61**，按词切分、对无空格中文不做子串切分：输入 `指数` 无法命中 `二元指数分布.html` 的内容（docs/03 §3.1 注释与宪法 C.2 声称的「FTS5 trigram」未落到建表语句）。FR-SEARCH-01/02 的中文子串检索与 A.4-11 的 3 字符边界均以 trigram 为前提，故 v2 迁移是 M2 的硬前置。

### 2.2 v2 迁移 `0002-search-trigram`

单事务、DDL 与 `user_version=2` 原子生效（继承 M1 §3.2 执行器语义，失败回滚 + fail-fast 阻止启动）：

```sql
-- ① 新建 trigram 表：case_sensitive 默认 0（索引大小写不敏感，且可优化 ≥3 连续字符的 LIKE/GLOB——A.4-11 退化面由此规避）
CREATE VIRTUAL TABLE node_fts_new USING fts5(name, body, tokenize = 'trigram');
-- ② 复制旧索引：rowid 透传（= node.id）；M1 不变式「回收站节点无 FTS 行」保证旧表只含活节点行，无需过滤
INSERT INTO node_fts_new (rowid, name, body) SELECT rowid, name, body FROM node_fts;
-- ③ 换名（FTS5 影子表随 ALTER RENAME 迁移）
DROP TABLE node_fts;
ALTER TABLE node_fts_new RENAME TO node_fts;
-- ④ 子树 CTE 与回收站树下钻所需的全量父指针索引（既有 idx_node_parent 为活行部分索引，不覆盖回收站行）
CREATE INDEX idx_node_parent_all ON node(parent_id);
```

- **复制而非重抽取**（方案 A 裁决）：旧索引行就是 M1 同事务写入的抽取文本（§7.7 规则同源），迁移零 content BLOB 读取，不触碰交互路径预算；「从 content 重抽取」方案（B）因启动装配路径读全库 BLOB、需分批事务复杂化而否决。
- **漂移对账兜底**：换名前断言 `旧表行数 == SELECT COUNT(*) FROM node WHERE deleted_at IS NULL AND id <> 1`（非根活节点数——根节点由 v1 种子建立、无 node_fts 行，M1 写侧仅对 `createNode` 产出的非根节点建索引，故对账口径排除 id=1）。不平即抛错回滚、阻止启动（既有 fail-fast 通道），杜绝把漂移复制进新表。
- **迁移冻结规则**：v2 落地后，既有迁移一律只追加不回改；v1 曾原地修改属「未发布特例」，不再开先例。

## 3. 模块结构与子树定位改造

### 3.1 目录与边界

```text
src/main/search/
├── queryBuilder.ts    # 纯函数：输入 → 通道选择 + MATCH 串 / LIKE 参数组（无 IO、无 db）
├── snippetParser.ts   # 纯函数：snippet 标记文本 → {text, ranges[]}
└── searchService.ts   # createSearchService(db)：查询执行、排序、分页、filters（纯读，不开写事务）
src/main/vfs/
└── subtreeScope.ts    # 新增：递归 CTE SQL 模板与「按 id 集合」的子树语句工厂，vfsService 与 searchService 共用
```

依赖方向：`search → vfs/subtreeScope`（主进程内部同层复用，B.2 四大目录边界不禁止）；`shared` 契约照旧单一来源。

### 3.2 子树定位统一改 parent_id 递归 CTE（遗留项根治）

身份来源从「路径前缀」改为「parent_id 传递闭包」：

```sql
WITH RECURSIVE subtree(id) AS (
  SELECT @rootId
  UNION ALL
  SELECT n.id FROM node n JOIN subtree s ON n.parent_id = s.id
)
```

- **替换范围**：M1 的 10 处路径前缀谓词（trash/restore/purge 的 FTS 删除·软删·还原·物理删·计数，rename/move 的级联 UPDATE 与 affectedCount 计数）全部改 `id IN (subtree)` 形态；rename/move 的路径值仍按行 `@newPath || substr(...)` 计算，但作用域由 id 集合圈定。
- **状态锚定整体撤除**：软删子树整树同态不变式（创建/还原要求活父链、trash/restore/move 均整树原子）保证任一子树内行同态，CTE 按身份收敛后无需 `deleted_at` 过滤，孪生树互不沾染；「同路径双回收站树」场景由已知限制转为**通过性回归用例**（两棵各自独立 purge/restore）。
- 性能：递归下钻每层走 `idx_node_parent_all`（§2.2 ④），万级子树毫秒~十毫秒级，处于交互预算内（§7.2 基准实测验证）。

### 3.3 其余 M1 遗留项落点（行为微调，不涉结构）

| 项 | 终态行为 |
| --- | --- |
| ListChildren 互斥 | `ListChildrenRequestSchema = z.union([z.strictObject({parentId}), z.strictObject({virtualPath})])`——两字段并存或携带多余字段均 `E_IPC_BAD_PAYLOAD`；服务层不变 |
| moveNode 同父短路 | `target.id === row.parent_id` 时返回 `{affectedCount: 0}`，不广播 `moved` 以外的语义变化（仍广播，事件 affectedCount 0，M4 面板可无操作刷新） |
| restoreNode 新鲜度 | 事务内还原 UPDATE 后以还原时刻值合并返回（`toNodeMeta({...row, deleted_at: null, updated_at: now})`，避免同事务重读的不可达防御分支），返回/广播 `updatedAt` 为还原时刻新值；测试直查库比对一致性 |

## 4. 查询管线与搜索语言（已确认：空格 AND + 引号短语）

`queryBuilder` 纯函数管线：

1. 输入 `trim` + **NFC 规范化**（名称入库即 NFC，查询同法对齐；trigram 索引大小写不敏感，拉丁字母大小写无需再归一）；
2. 空白（连续空格/制表）切分为词项；双引号包裹段合并为**短语项**；词数上限 **8**（超限整条拒绝 `E_IPC_BAD_PAYLOAD`），单项 ≤255 码点（复用名称长度上限量级）；
3. 服务层按「项」构造 MATCH 串：每项转双引号短语、内部 `"` 加倍转义，项间 `AND` 拼接——用户输入**不可能注入**列选择/`NOT`/前缀等高级语法；
4. **通道选择（整条查询单一通道）**：
   - 全项 ≥3 Unicode 字符 → **索引通道**：`node_fts MATCH @built`，trigram 短语=子串，AND 语义精确；
   - 含 <3 字符项 → **LIKE 回退通道**（docs/03 R2 既定降级，整条同走此通道保 AND 可组合）：活节点 `name LIKE ? ESCAPE '\'`、活正文 `node_fts.body LIKE ? ESCAPE '\'`（转义 `\%_`）。**ESCAPE 仅出现在回退通道**——回退本即线性扫描，不受 A.4-11「带 ESCAPE 无法走索引」约束；索引通道无 ESCAPE 形态。
   - 空查询/纯空白 → `E_IPC_BAD_PAYLOAD`（不新增错误码）。
5. LIKE 回退通道无相关性分数：按 `updated_at DESC, id ASC` 排序（与索引通道 tie-break 同形，契约 `score` 省略字段）。

## 5. 排序、上限与分页（已确认：bm25 加权）

- **索引通道**：`ORDER BY bm25(node_fts, 10.0, 1.0) ASC, updated_at DESC, id ASC`——文件名权重 10:正文 1（bm25 分数越小越优）；同分按更新时间降序、再 id 升序，保证分页稳定。
- **上限与分页**：`limit` 默认 **50**、硬上限 **200**（超限入参截断为 200）；`offset ≥ 0` 分页，越界返回空数组（不算错误）；`truncated` 定义为**还有未返回的命中**（`offset + hits.length < total`），与入参是否被截断无关；`total` 为命中总数（精确 COUNT 子查询——10k 活行级可控，P95 基准含此成本）。
- **matchIn 判定**：对命中行求 `name MATCH @built` / `body MATCH @built` 布尔位，合成 `'name'|'body'|'both'`。

## 6. 响应契约与高亮片段（已确认：文本 + 命中区间）

```text
shared/search-contract.ts（新建，单一来源；通道常量入 shared/ipc.ts：searchQuery = 'search:query'）

SearchQueryRequest   { keyword: string, filters?: { nodeTypes?: ('dir'|'file')[], underPath?: string }, limit?: number, offset?: number }
SearchHit            { node: NodeMeta, matchIn, score: number | null, nameSnippet: Snippet, bodySnippet: Snippet | null }
Snippet              { text: string, ranges: { start: number, end: number }[] }   # start/end 为 JS UTF-16 码元偏移，渲染端直接 slice 套样式
SearchQueryResponse  { hits: SearchHit[], total: number, truncated: boolean }
```

- **区间语义**：`ranges` 与查询命中项对应、可不连续（多词多段）、允许重叠（同文多命中）；`start` 升序。区间计算在服务层完成：body 片段用 FTS5 `snippet(node_fts, 1, '\u0002', '\u0003', '…', 12)`（正文列、估算 12 token ≈ 36 字上下文）输出带控制字符标记的文本，`snippetParser` 解析出纯文本 + 码元区间；name 片段用对查询词在 NFC + `toLowerCase()` 下 `indexOf` 定位（大小写不敏感口径与索引一致）。**渲染器（M4）只按区间着色，不接收任何 HTML**（无 XSS 面，样式归渲染层）。
- **LIKE 通道的片段来源**（不走 `snippet()`，无索引标记可用）：对活节点行按首个命中词在 NFC+`toLowerCase()` 下的 `indexOf` 位置，截取 ±36 码点上下文窗口构造 `bodySnippet`（多区间规则与索引通道一致）；正文极长时仅扫首个命中窗口，成本有界。
- **filters（FR-SEARCH-03 P1，M2 一并实现）**：`nodeTypes` 白名单过滤；`underPath` 先 `vfs:resolvePath` 同语义解析为活节点 id，再以 §3.2 CTE 圈定子树——避免 M4 触碰契约二次返工。
- 无广播事件：搜索纯读，不发 `vfs:changed`；preload 桥新增一个具名包装 `searchQuery()`（A.7-4 桥接面最小化）。

## 7. 一致性、维护与性能基线

### 7.1 索引一致性

- 「删除后立即可搜不到」（FR-SEARCH-04）由 M1 不变式（trash 先删 FTS 行、restore 同事务重建）自然成立，M2 加集成断言锁死：trash→查询 0 命中；同名单秒级重建后旧内容不可检索、新内容可检索；restore→命中恢复。
- `'optimize'` 仅限空闲期（A.4-10），M2 **不排任何自动 optimize/merge 任务**；普通 FTS5 表无 external-content `'integrity-check'`，漂移防线 = v2 迁移期对账断言（§2.2）；「索引重建修复例程」登记 M5 设置页执行项（不入本文）。

### 7.2 性能基准与宪法回填（NFR-01/03，A.5-4 重校）

新增文件库集成基准（临时目录真实 db，替代 M1 的 `:memory:` 名义口径）：

| 指标 | 基准用例 | 目标 |
| --- | --- | --- |
| 万行单事务写入**含 node_fts 插入**（服务层语句形态，非裸 SQL） | 计时 X' | 供 A.5-4 重采 |
| `search:query` 万级文档、混合关键词 | 50 次采样取 P95 | < 200ms（NFR-03，含 bm25+COUNT+snippet 全成本） |
| 冷启动：打开 10k 级文件库 + 迁移就绪（v2 已生效路径） | 计时 | < 2s（NFR-01 真实口径） |
| v2 迁移自身耗时（10k 级库换表） | 计时 | 记录入基准报告，纳入启动预算核算 |

A.5-4 回填沿用 M1 流程与公式（`Z = ceil(max(交互写路径实测, 交互查询实测) × 10 / 100) × 100`，下限 200ms；「交互查询」取万行 listChildren 与搜索 P95 两者较大值）：先记 CHANGELOG、再句尾追加 AGENTS.md 实测结论（原句不动）、删/改 TASK.md 对应行；若新实测推翻 200ms 档位，以新值为准。LIKE 回退通道（正文全扫）明确标注**不承诺** P95 红线，10MB 级库预期十毫秒~百毫秒，属短查询体验降级（docs/03 R2 既定）。

### 7.3 错误处理与日志

- 错误：载荷非法/超限 `E_IPC_BAD_PAYLOAD`；运行期 SqliteError 走 M1 `mapSqliteError` 既有映射表；**不新增错误码**（「无结果」是正常空数组，非错误）。
- 日志（docs/03 §7.4 + 全局 §二）：info 记录查询长度、通道、命中数、耗时；**不落关键词原文**（用户数据最小化）；warn 记录空/超限/畸形参数拒绝；error 走映射后统一面。

## 9. 裁决汇总（评审对照）

1. M2 交付=服务+契约；搜索面板 UI 归 M4（用户确认）。
2. 查询语法=空格分词多关键词 AND + 双引号短语；高级语法不透传（用户确认）。
3. 排序=bm25(node_fts, name 10 : body 1)，tie-break `updated_at DESC, id ASC`（用户确认）。
4. 高亮片段=服务端纯文本 + UTF-16 码元命中区间，契约零 HTML（用户确认）。
5. trigram 转换=**v2 复制换表**（方案 A），零 BLOB 读取；行数对账不平阻止启动（用户确认）。
6. 子树定位全面改 parent_id 递归 CTE 并撤除状态锚定，同路径双回收站树转为通过性用例；v2 同批增 `idx_node_parent_all`；v2 后迁移只追加不回改。
7. filters（FR-SEARCH-03 P1）M2 一并实现于服务层；查询词项数上限 8（超限拒绝）；LIKE 回退整条查询同走降级通道、不承诺 P95、片段改 indexOf 窗口截取（控制器自主判断，随 spec 一并评审通过）。
8. 不新增错误码；搜索无广播事件；日志不落关键词原文。
9. `optimize` 不自动执行；索引修复例程后置 M5。
10. A.5-4/NFR-01 基线改文件库+含 FTS 服务层路径重测，按修宪流程回填（公式不变）。
