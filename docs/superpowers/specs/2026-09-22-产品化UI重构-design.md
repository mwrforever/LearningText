## 1. 定位与交付边界

M6 交付四件事：**①** 应用壳层全量重构为 VS Code 式布局（自绘标题栏 + 应用内菜单、活动栏、侧栏、编辑区标签、状态栏、欢迎页、设置标签页，全量图标化）；**②** HTML 文档所见即所得编辑（渲染面即编辑面，协议编辑桥 + 保存管线复用 + 刷新抑制）；**③** 数据保存位置用户可选 + 原子迁移 + NSIS 安装位置可选；**④** `start.sh` / `start.bat` 启动脚本。

**纳入范围（P0）**：FR-SHELL-01/02（修订版）、FR-RENDER-08、FR-EDIT-01（限定版）/FR-EDIT-05、FR-AUX-03（修订版）、docs/03 §7.1 storage 双通道、E_STORAGE_* 错误码。

**不在范围**：搜索索引重建接线（设置页 disabled 占位按钮按「无占位功能」原则**移除**，TASK.md 条目保留）；macOS 签名公证、fuses 清单、release 工作流（TASK.md 既有 M6 后续项）；预览 DevTools（FR-RENDER-05 维持 P1 后置）；重建滚动同步（已退役，见 §10 D5）。

**退役清单（本里程碑删除的既有能力）**：`scrollSync.ts` 与编辑器↔预览滚动同步双向桥（含 D13 回环抑制、D14 滚动同步开关钮）；D20 媒体弱选中双源（`previewNode`/`previewSource`/`previewDisplayNode`——媒体文件一律开标签，`FR-EDIT-04` 修订版）；设置页「重建搜索索引」占位按钮。既有 E2E 中依赖上述能力的用例随批次删除/改写。

### 2.2 自绘标题栏与窗口（宪法 B.5 红线全部不变）

- 窗口创建：`titleBarStyle: 'hidden'` + `titleBarOverlay`（Windows/Linux：`{ color, symbolColor, height: 40 }`，原生 ─□✕；macOS：系统红绿灯 + `trafficLightPosition`）。**平台探针结论（2026-09-22 回填，Windows 10.0.26200 / Electron 44.3.0 实证）**：① `Menu.setApplicationMenu` 已设时 `win.isMenuBarVisible() === false`——原生菜单栏在 hidden 形态下不渲染，应用内菜单方案成立，application menu 保留承载加速器与 mac 系统菜单；② overlay 生效：渲染页可读 `env(titlebar-area-height) = 40`（与配置一致）、`titlebar-area-width` = 窗口宽 − 原生控制钮区。Linux overlay 可用性未本机实证：Linux E2E 对 overlay 断言平台豁免，矩阵若证不可用则登记 TASK.md 决策（不阻塞主线）。
- 应用内菜单：手拷 shadcn `menubar` registry 模板（EALLOWSCRIPTS 不可用，M5 手工落模板先例）至 `components/ui/menubar.tsx`。菜单树与现行 `menu.ts` 命令**一一对应**（文件：新建文件/新建目录/保存/导入/导出/设置…/退出；搜索：快速打开/全局搜索；导入导出：导入…/导出…），点击即 dispatch 既有 `shell:command`，**禁止新增未实现功能项**（FR-SHELL-02）。原生 `Menu.setApplicationMenu` 保留（承载加速器与 mac 系统菜单栏）；mac 不渲染应用内菜单（`window.api.platform` 判定，preload 新增只读字段）。
- drag/no-drag：标题栏容器 `-webkit-app-region: drag`，菜单钮/图标等交互子元素 `no-drag`；双击最大化由 overlay 原生承载。
- **主题联动**：`titleBarOverlay` 颜色随主题更新——`settings:set` handler 检测 `appearance.theme` 变更后调 `window.setTitleBarOverlay()`（主进程内聚，不新增 IPC 通道）；初始值由启动时读取的设置决定。overlay 颜色用主题 tokens 的硬编码字面值（overlay 不支持 CSS 变量），亮暗两套常量集中于 shared 常量。
- `attachWindowCloseGuard` 脏关窗拦截链不变。

### 2.3 活动栏与侧栏

- 活动栏 `lt-activity-bar`（w-12，muted 面）：资源树 `Files`、搜索 `Search`、回收站 `Trash2`；底部固定设置 `Settings`（打开设置标签页，非视图切换）。选中态：左侧 2px accent 指示条 + 图标前景色切换。**图标钮一律 `aria-label` + `title` tooltip**（可访问性红线）。
- 侧栏 `lt-sidebar`：随活动视图互斥渲染既有 TreePanel / SearchPanel / TrashPanel 三态内容（现有 `view` state 语义平移为活动视图）；头部为「面板标题 + 图标操作钮」（资源树：新建目录 `FolderPlus`、新建文件 `FilePlus`、折叠 `PanelLeftClose`；搜索/回收站保持各自操作图标化：返回 `ArrowLeft`、清空 `Trash2` 等）。宽度拖拽复用 `layoutModel` 纯函数，比例沿用 0.15–0.6 钳制。
- 树行操作图标化：行内「⋯」→ `MoreHorizontal` 图标钮；move/rename/delete 菜单项加图标。所有工具栏文字钮替换为图标钮 + tooltip。

### 2.4 标签栏与标签模型（tabModel 扩展）

- 标签形态扩展为可辨识联合：`{ kind: 'doc'; meta: NodeMeta; dirty: boolean } | { kind: 'settings' }`；`kind:'doc'` 按 `previewableMime` 细分画布类型（html / codemirror 文本 / image / audio）。MAX_TABS = 20 仅约束 doc 标签；settings 标签至多一个、不占额。`activeId` 语义不变（settings 激活时记 `activeId = 'settings'` 哨兵）。
- 标签栏渲染：文件类型图标（html→`FileText`、css/js→`FileCode`、媒体→`Image`/`Music`）、名称、脏态**小圆点**（destructive 色，替代「未保存」文字）、关闭 `X` 钮（hover 显形）；settings 标签显示 `Settings` 图标 + 「设置」。`lt-tabbar` 锚点保留。
- 打开语义（D6）：树/搜索/欢迎页/快速打开点击任何可打开文件**一律开 doc 标签**（HTML→画布、文本→CM、媒体→img/audio）；二进制且非媒体仍拒绝开签 + toast（现状保留）。

### 2.5 欢迎页（首页重构）

无激活 doc 标签且未开设置时，编辑画布区渲染 `lt-welcome`：产品名 + 一句话定位；主操作三钮（新建文件 / 导入… / 快速打开 Ctrl+P，图标+文字）；「最近打开」列表（`settings.recent.opened` 前 10 条，点击开签；空态文案「暂无最近打开的文档」）；快捷键提示卡（Ctrl+S 保存 / Ctrl+P 快速打开 / Ctrl+Shift+F 全局搜索）。纯呈现组件，数据经 props 注入。

### 2.6 状态栏

`lt-statusbar`（h-6，accent 弱化面）：左＝保存态（存在脏标签：destructive 圆点 +「有未保存更改」；否则「已保存」）+ 节点统计（「N 个文档」从树根计数缓存，不做实时精确承诺——首屏一次性 listChildren 汇总 + vfs:changed 增量近似）；右＝主题三态循环钮（Sun/Moon/Monitor 图标，tooltip 显示当前态）+ 设置齿轮。保留既有状态栏插槽语义。

### 2.7 布局记忆（settings schema v3→v4）

`shell.layout` 改为 `{ sidebarCollapsed: boolean; sidebarWidthRatio: number(0.15–0.6); activityView: 'tree'|'search'|'trash' }`（`SETTINGS_SCHEMA_VERSION` 3→4）。迁移 `migrateV3ToV4`：全部旧域保留用户值；`treeWidthRatio` → `sidebarWidthRatio`；`treeCollapsed` → `sidebarCollapsed`；`activityView` 默认 `'tree'`；`editorCollapsed`/`previewCollapsed`/`previewWidthRatio` **丢弃**（单画布模型下无对象）。其余六域零改动。`layoutModel` 比例纯函数保留复用。

## 3. 所见即所得编辑画布（批次②核心）

### 3.1 协议编辑桥（`vfsProtocol.ts` 注入脚本扩展）

现有 `PREVIEW_RECEIVER` 注入点、注入位置（最后一个 `</body>` 前）、不参与 content_hash/ETag、304/206 不注入等纪律**全部不变**。注入脚本扩展（仍单一 `<script>`，串内禁字面 `</script>`，标记 `data-lt-injected="1"`）：

| 方向 | 消息 | 语义 |
| --- | --- | --- |
| 父→子 | `{type:'lt:edit-enable'}` | `document.body.contentEditable = 'true'`（spellcheck=false）；开始监听 `input` |
| 父→子 | `{type:'lt:edit-disable'}` | 停止编辑态（会话关闭路径用） |
| 父→子 | `{type:'lt:css-swap', …}` | 既有 CSS 热替换，保留 |
| 子→父 | `{type:'lt:doc-edit', html: string}` | iframe 内 `input` **逐输入即时**上报序列化 HTML（§3.2；批次④修正：原 200ms setTimeout 去抖在沙箱 iframe 内可被渲染器计时器搁置无限期延迟（E2E 探针实证），上报尾部丢失即保存尾部丢失——即时上报后写侧节奏由父窗 SaveController 去抖全权承担） |

`lt:scroll-ratio` / `lt:scroll-report` 注入段删除（滚动同步退役）。

### 3.2 序列化契约（注入桥内实现，jsdom 运行时用例覆盖）

序列化器（`ltSerialize`）落位于 §3.1 注入桥脚本内（iframe 是文档 DOM 的唯一持有方，渲染层无序列化时机）：`cloneNode(true)` → 移除 clone 内全部 `[data-lt-injected]` → 移除 `body` 的 `contentEditable`/`spellcheck` 属性 → doctype 重建（`document.doctype` 的 name/publicId/systemId，缺失则省略 doctype 行）→ 返回 `'<!DOCTYPE …>\n' + outerHTML`（无 doctype 则裸 outerHTML）。**注入脚本永不落库**——否则每轮保存累积脚本且污染 content_hash。注入体语法由集成测试 `new Function` 编译守卫，序列化行为（doctype 三态/注入剥离/contentEditable 清除）由 jsdom 真实执行注入体的运行时用例覆盖。

### 3.3 渲染层画布（`features/canvas/`，替代 PreviewPanel 的 HTML 职责）

- **每 HTML 标签一个 iframe 会话**（`canvasSessions` Map，与 `tabSessions` 平行；保活不销毁，非激活仅 `hidden`）——切标签保留浏览器原生撤销（撤销 = iframe 内 Ctrl+Z，沙箱不拦截；重启丢失，docs/01 M5 边界明示）。iframe 沙箱属性维持 `sandbox="allow-scripts"`（opaque origin 红线，B.5-7 不变）。
- 生命周期：开签 → 建 iframe（src=vfs://local+virtualPath）→ `onLoad` 后 postMessage `lt:edit-enable`；路径变更（rename/move）→ 销毁重建该会话（key 变更）；关签 → `lt:edit-disable`（尽力而为）+ 移除会话 + SaveController `tabClosed`。
- **保存接线**：SaveController 纯状态机（saveModel/saveController）**零改动**复用；装配点改两处——`getDoc(nodeId)` 读 canvasSessions 中该节点最新 `lt:doc-edit` 缓存；`edit(nodeId)` 由 `doc-edit` 消息驱动（媒体/文本标签路径不变）。去抖设置 `preview.debounceMs`/`editor.autoSaveMs` 语义原样（写侧时机，与编辑 UI 形态解耦）。
- **刷新抑制（D7）**：`vfs:changed` 的 `written` 事件命中「存在画布会话的节点」→ 一律跳过 `location.replace`（自己写的保护光标与撤销；外部写入的导入/还原场景同样跳过，用户经画布浮动「从库重新加载」钮 `RotateCw` 显式拉取——**实现裁决（批次②落地修正）：脏态下重新加载钮禁用**（tooltip 引导先保存/撤销），替代原「confirm 确认丢弃」设计——避免引入 SaveController 的「重置脏态」旁路语义，交互更诚实）。`text/css` 热替换通道保留并迁入画布组（written 命中 text/css → 拉新文本对全部 HTML 画布广播 `lt:css-swap`，各文档注入桥按自身 link 匹配，零整页重载）。
- 编辑输入回路：`lt:doc-edit` → 更新会话缓存 + `saveController.edit(nodeId)`（Workspace 单点接线，替代 CM updateListener 在 HTML 路径的位置）。

### 3.4 EditorPanel / CodeMirror 归宿

EditorPanel 与全部 CM 基础设施**完整保留**，服务 CSS/JS/TXT 等非 HTML 文本标签；HTML 不再进入 CM（FR-EDIT-01 修订版）。`appearance.editorFontSize` 继续作用于 CM（设置项改述「源码编辑器字号」）；WYSIWYG 画布字号由文档自身样式决定，**不注入任何 UA 样式**（保真红线）。删除 `scrollSync.ts` 及 EditorPanel/PreviewPanel 内同步接线与测试。

## 5. 数据目录指针与迁移（批次③）

### 5.1 指针文件

`<userData>/data-dir.json`，zod `strictObject({ root: string | null })`。启动装配链在 `resolveDataDir` 前插入 `readDataDirPointer(userDataRoot)`（纯函数 + 注入式读取，`dataDir.ts` 落位）：缺失/解析失败/schema 不中 → warn 回退默认（返回 `null`），**不阻断启动**。`effectiveRoot = pointer.root ?? userDataRoot`；数据布局仍为 `<effectiveRoot>/LearningText/`（用户选父目录，套层与默认形态同构，D8）。

### 5.2 迁移服务（`src/main/storage/`，新域）

`changeDataDir(targetDir)` 流序（全部可单测的纯步骤 + 注入式 IO）：

1. 校验：目标存在且为目录、可写探针、`path.resolve(newRoot) !== path.resolve(currentRoot)`（不等才继续）、**目标位置已存在 `LearningText` 数据目录时拒绝**（迁移是「建立新位置」而非「合并」——同时保证失败清理只删本次创建内容，不误伤用户既有文件）；任一不过 → `E_STORAGE_INVALID_TARGET`。
2. `checkpoint(TRUNCATE)`（既有 BackupService 双语义 checkpoint 复用）→ `db.close()`（A.4-1 优雅关库；close 失败 → `E_STORAGE_MIGRATE_FAILED`，**不 relaunch**，库仍可用）。
3. 复制：dbFile、`settings/`、`backups/`（含 last-backup.json）→ 新布局 `ensureDataDir`。
4. 原子写指针（tmp + rename，userData 直下）。
5. `requestRelaunch()`（既有）。**步骤 3/4 任一失败**：清理已建新目录树（仅删本次创建内容）、不写指针、仍 relaunch（旧指针完好，旧位置照常打开）——失败代价 = 重启，非数据损坏（D9）。
- `will-quit` 关库 handler 加已关闭守卫（db 为 null / 已 close 时跳过）。
- IPC：`storage:get-info`（返回 `{ root, dbFile, backupsDir, settingsFile, custom: boolean }`）/ `storage:change-data-dir`（`{ targetDir: string(min 1) }`，目录串经 `dialogProducedDirs` 登记簿校验——`pick-directory` 产出即登记，复用既有信任边界范式）。两通道按 A.7-3 走 Result DTO + zod `safeParse`；错误码 `E_STORAGE_INVALID_TARGET` / `E_STORAGE_MIGRATE_FAILED` 落 `errors.ts` 与渲染层中文映射。

### 5.3 打包（安装位置可选）

## 6. 启动脚本（`scripts/start.sh` + `scripts/start.bat`）

幂等生产形态启动：node 存在检查 → `node_modules` 缺失则 `npm ci` → `npm run rebuild`（ABI 保证）→ `npm run build` → `npm start`。中文步骤输出（echo），失败即停（`set -e` / 逐条 `if errorlevel`），bat 用 `%~dp0..`、sh 用 `cd "$(dirname "$0")/.."` 定位仓库根。POSIX shell 纪律仅约束 husky 钩子，本脚本是用户侧便捷脚本，sh 版按 bash 写（Git Bash 环境声明）。

## 7. 错误处理与日志

- 迁移全链路按 §5.2 错误码分支；主进程 info 记「迁移开始/完成（含源与目标根）」、warn 记指针回退与校验拒绝、error 记复制失败（含 IO 错误码）；**禁止打印库内容**。
