## 1. 定位与交付边界

M3 交付「浏览器级保真实时预览」的完整管线：`vfs://` 自定义协议（SQLite BLOB → HTTP 语义响应）、沙箱 iframe 与 CSP、实时刷新链路（去抖 → 写 → 事务提交 → 广播 → 重载）、最小设置通道、承载上述能力的**最小预览工作台 UI**，以及 E2E 主链路验证。

**纳入范围（P0，M3 实现）**：FR-RENDER-01/02/03/04 + NFR-04 + FR-SHELL-01 的「三栏」静态骨架（含 shell 插槽，不含折叠/记忆）。

**设计纳入、实现后置（P1）**：FR-RENDER-05 DevTools、FR-RENDER-06 滚动同步、FR-RENDER-07 CSS 热替换——本 spec 给出协议级设计（§7），实现归 M4/M5 批次（已登记 TASK.md）。

## 2. vfs:// 协议设计

### 2.1 URL 身份结构（裁决 D1：路径式，已确认）

`vfs://` URL 以**虚拟路径**为身份：`vfs:///笔记/web/index.html`。iframe src 直接使用虚拟路径，相对资源引用（`./style.css`、`img/a.png`、`../共享/x.js`）与根相对引用（`/笔记/web/x.css` → `vfs:///笔记/web/x.css`，空 host 下成立）由 Chromium 标准 URL 解析落在同一 VFS 子树——核心价值即**把相对路径解析委托给标准解析器，不自研重写器**；与系统浏览器以 `file://` 打开同目录文档的行为同构（FR-RENDER-01/02 保真来源），docs/03 §2.2-3「无需改写用户 HTML」由此成立。

- 被否方案：id 基式（`vfs://n5/index.html`）——rename/move 后 URL 不失效，但相对解析后 id 与名字混合、用户 HTML 绝对路径引用需兼容层，保真度受损。
- rename/move 后旧 URL 失效是浏览器同款行为；刷新链路由渲染层持有 nodeId、重载前经最新路径解析（§4.3），自然落新地址。
- query string 被协议**忽略**（不参与身份）；且**禁用作 cache-busting**——加 query 破坏 ETag/304 收益（§4.2）。

### 2.2 路径解析语义

1. handler 只接受 path 部分；query string 忽略（见 §2.1 禁令），fragment 忽略。
2. 逐段 `decodeURIComponent` 后按 `/` 连接还原虚拟路径；**禁止整串 decode 后再分段**（编码后的 `/`（`%2F`）不得充当路径分隔符——先按原始 `/` 分段，再逐段解码）。
3. 归一化拒绝：解码后任一段为空、`.`、`..`，或多重斜杠产生的空段——整条请求 **404，不做 clamp**（用户评审钉死：越界即 404，不裁剪到根、不静默归一）。库内 `virtual_path` 本身无这些形态，匹配天然安全（FR-RENDER-04「无法逃逸 VFS 之外」：解析只查 `node` 表，无文件系统接触）。
4. 查询条件：`virtual_path = ? AND deleted_at IS NULL`（活行；回收站资源不可达）。命中 `node_type = 'file'` 才响应，目录请求 404（`vfs://` 是资源出口，非列表出口）。
5. 解析不到活行 → 404，响应体不含任何库内信息（不泄露路径/表结构，B.5-2 同款纪律）。

### 2.3 响应语义

| 项 | 语义 |
| --- | --- |
| Content-Type | `mime.ts` 的 `lookupMimeType(fileName)`（M1 既有表，M1 注释已声明 M3 共用）；未识别回退 `application/octet-stream` |
| ETag | `W/"<content_hash>"` 弱校验器——content_hash **在 createNode/writeFile 写路径算好入库**（M1 既有列），响应时直读、零额外计算 |
| Cache-Control | `no-cache`——允许缓存 + 每次使用前强制 revalidate，这正是 304 收益的前提（`no-store` 会干掉 304，禁用） |
| CORS | 所有响应统一带 `Access-Control-Allow-Origin: *`——opaque origin 下沙箱文档的 `fetch()` 以 `Origin: null` 发起跨源请求，无此头即使 `connect-src vfs:` 也会被 CORS 拦截；`*` 无凭据（沙箱无 cookie），不放大攻击面 |
| Content-Security-Policy | 仅 `text/html` 响应注入（§3.2 值）；其余 MIME 不注入 |
| Accept-Ranges / 206 | `bytes`；`Range: bytes=start-end` 单区间 → 206 + `Content-Range: bytes start-end/total`，body 为 Buffer 切片（`Buffer.subarray`，零拷贝语义）；语法非法或越界 → 416；**多区间不支持 → 忽略 Range 头按 200 全量**（RFC 7233 允许） |
| HEAD | 与 GET 同头无体（健全性） |
| 416/404 响应体 | 固定短语（如 `Range Not Satisfiable` / `Not Found`），不含库内细节 |

### 2.4 scheme 注册（用户评审钉死：standard）

`registerSchemesAsPrivileged` 在 app ready 前声明 `vfs` 为 **standard scheme**（非 standard 时相对 URL 解析**静默失败**——标准解析器的基路径语义是 §2.1 的地基），并按需开放 `supportFetchAPI`、`stream` 特权（fetch 通道供 §7.3 热替换与页面内 fetch 用例）。`protocol.handle('vfs', handleVfsResource)` 在窗口创建前注册（B.3-1 装配顺序）。响应一律走 Web `Response` 对象（与 appProtocol 的 `net.fetch` 同构签名）。

**TASK.md 待调研项收口**：「protocol.handle API 细则」的 standard/CORS/Response 语义已由本 spec 定死，M3 计划仅剩特权字段组合的最小探针实测。

### 2.5 实现形态

`src/main/protocol/vfsProtocol.ts` 导出 `handleVfsResource(request: Request): Promise<Response>`；BLOB 读取经存储层**同步短临界区**单行 `SELECT content FROM node ...`（宪法 A.1-7 允许；预览加载属用户显式导航，非批量路径）。

### 2.6 日志取舍

协议 handler 高频（一个文档 = 主文档 + N 资源请求）：200/304/206 **不记日志**（全局 §二「禁止循环内大量日志」；资源加载失败由 iframe 内浏览器控制台呈现，FR-RENDER-02 明示）；仅 handler 意外异常记 error（含堆栈与 URL path）。

## 3. 沙箱与 CSP

### 3.1 iframe 沙箱属性（渲染层 PreviewPanel）

```html
<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" src="vfs:///笔记/web/index.html" />
```

- `sandbox="allow-scripts"` 且**不含** `allow-same-origin`：文档为 opaque origin——**localStorage/sessionStorage/indexedDB 访问抛异常**、cookie 不可用、XHR 同源能力禁用、表单提交/弹窗/顶层导航全禁（对应 token 不给）。脚本可运行（HTML 生态常态，保真），但拿不到任何敏感能力。
- `referrerpolicy="no-referrer"`：资源请求不携带引用来源。
- **已知边界（与 CDN broken 同类，模型必然输出）**：依赖 localStorage/cookie 的文档在预览中抛异常或静默失效；这是「关住而非过滤」安全模型的既定取舍，不做任何绕过。
- 父子通信（P1 滚动同步/热替换预埋）：仅 `postMessage`，opaque origin 下 targetOrigin 用 `*` 收发（内容无敏感能力，消息协议见 §7）。

### 3.2 CSP 值（裁决 D2：断外链，已确认；connect-src 修订为 vfs:）

仅对 `text/html` 响应注入：

```text
Content-Security-Policy:
  default-src 'none';
  script-src vfs: 'unsafe-inline';
  style-src vfs: 'unsafe-inline';
  img-src vfs: data: blob:;
  font-src vfs: data:;
  media-src vfs: data: blob:;
  connect-src vfs:;
  object-src 'none';
  frame-src 'none';
  form-action 'none';
  base-uri vfs:
```

- 资源仅可来自 `vfs:`（断 http/https 外链）——用户库中 HTML 成为本机数据的出网面被关闭（B.5-3 受限 CSP + 最小权限）；引用 CDN 的文档预览中 broken 是既定取舍（裁决 D2），下载入库即可恢复。
- **`script-src 'unsafe-inline'`（用户评审必点）**：内联 script 是海量 demo/真实文档的常态，禁用即破坏保真；**真正防外泄的是 `connect-src vfs:` + opaque origin + 断外链**，inline script 的剩余面与「以系统浏览器打开同一文档」一致。
- `connect-src vfs:`（用户评审修订，原空值）：允许页面内 `fetch`/XHR **只对本库**（VFS 内 JSON 数据文件是合理用例）；跨源 CORS 头见 §2.3。断外网能力不变（`vfs:` 之外的 connect 全部违规）。
- `frame-src 'none'` 禁嵌套 iframe；`object-src 'none'` 禁插件；`base-uri vfs:` 防 `<base>` 劫持相对解析；`form-action 'none'` 禁表单外发。

## 4. 实时刷新链路

### 4.1 时序与因果链（write → commit → broadcast → reload，已确认）

```text
编辑器输入 → 渲染层去抖（preview.debounceMs，默认 300ms——用户评审定调：100ms 会在词中频繁触发，取值域 100–2000 不变）
  → vfs:write IPC → 主进程事务（内容+FTS+content_hash 同事务，一致性红线）→ 提交成功
  → 广播 { rev, event: vfs:changed{ type:'written', node } }（宪法 B.3-4，事务提交后；rev 见 §4.2）
  → PreviewPanel 收到广播且 node.id 匹配当前预览节点 → iframe 重载
```

- 「刷新仅发生在事务提交之后」由广播时序天然保证（广播在事务提交后发出，M1 已落地，B.3-4）。
- **保存动作立即刷新**：保存 = 立即发起 `vfs:write`（清空去抖计时器），广播到达后按上述链路重载。
- 去抖在**渲染层**（写之前），主进程不做去抖；去抖期间再次输入重置计时器（尾沿触发）。

### 4.2 重载语义与防撕裂版本号（用户评审新增）

**重载形态（钉死）**：`iframe.contentWindow.location.replace(url)`——**不加 cache-busting query**（query 破坏 ETag 重验收益，§2.1 禁令同源）；`replace()` 不向历史栈推入条目，连续编辑刷新不留导航垃圾。重载发起时 Chromium 对全部子资源带 `If-None-Match` 重验：内容未变 → 304 零传输；变更 → 200 新体（验收关键项「重载只有变更文件回 200」）。

**防撕裂（stale-load）协议**：iframe 加载中途库再被写（连续输入、加载耗时），本次 load 完成呈现的可能是中间态。机制（约十行代码）：

1. **rev 契约**：主进程存储层维护全局单调递增写事务计数 `rev`（每次写事务 commit 成功后 +1）；`vfs:changed` 广播 payload 包为可辨识联合 `VfsChangedBroadcast = { rev: number; event: VfsChangedEvent }`（shared 契约单一来源扩展，`WindowApi.onVfsChanged` 回调参数随之改型）。
2. **渲染端状态**：PreviewPanel 持 `latestRev`（已见广播的最大 rev）与 `loadedRev`（发起当前加载时锁定的 rev）；触发重载时 `loadedRev = latestRev`。
3. **load 完成比对**：`iframe.onload` 时若 `latestRev > loadedRev` → 立即再重载（直至追平）。iframe 内无逐资源 rev 校验（过度设计），比对粒度到「文档整体版本」即可。
4. rev 仅存在于主进程内存（重启归零）：与 iframe 状态同源生命周期，不持久化、不与旧值比较。

### 4.3 选中态与路径解析

工作台持有选中节点 `nodeId`；每次重载前以 `resolvePath`（M1 通道）反查当前 `virtual_path`——**不缓存路径**，rename/move 后第一次刷新即落新路径；`resolvePath` 失败（节点被 trash/purge）→ 预览区显示占位态（「文档不可用」），不重载旧内容。树刷新监听 `onVfsChanged` 全量事件（消费 `broadcast.event`），按事件形态做最小树同步（created/restored 增量插入、trashed/purged 移除、renamed/moved/written 刷新对应节点元数据）。

### 4.4 NFR-04 验收

「去抖到期后到预览完成重载 < 300ms（普通文档）」：本地路径 `vfs:` 加载 + BLOB 单行读 + 304/200 响应，链路无跨进程往返之外的开销；E2E 以宽松上限断言（集成测不出渲染重载真实耗时），实测值回填 TASK.md。

## 5. 最小设置通道（裁决 D4：M3 落地，已确认；版本化为新增接缝）

- 通道：`settings:get`（无参）→ `Result<SettingsData>`；`settings:set`（入参全量 `SettingsData`，渲染端 get→merge→set，避免 partial merge 语义）→ `Result<SettingsData>`。命名遵 B.2-5（docs/03 §7.1 既有通道名）。
- 契约单一来源：`src/shared/settings-contract.ts`——`SettingsSchema = z.strictObject({ schemaVersion: z.literal(1), preview: z.strictObject({ debounceMs: z.number().int().min(100).max(2000) }) })`；`SettingsData = z.infer<...>`。校验失败映射 `E_IPC_BAD_PAYLOAD`，**不新增错误码**。
- **存储层级与版本化（用户评审接缝要求）**：userData 下 `settings/settings.json`（A.2-1 应用专属子目录，目录层级为 M5 更多设置文件留缝）；文件首字段 `schemaVersion: 1` 定档。**M3 行为**：仅识别 v1——缺失文件/解析失败/不识别版本一律 warn + 回退默认值（300ms）；**M5 行为（接缝预留）**：引入版本号升位与旧版 → 新版迁移例程（读旧版 → migrate → 回写新版），键按域分组（`preview.debounceMs`，后续 `editor.*`/`app.*` 各自成组），M5 往缝里填而非重构存储形态。
- 读写：主进程独占；启动读一次进内存缓存（缺失/解析失败/schemaVersion 不识别 → 回退默认值 300ms 并 warn），`set` 时 zod 全量校验后**原子写**（写临时文件 + rename）。用户数据不因设置文件损坏而阻断启动（fail-fast 仅适用于数据库）。
- 主进程服务：`src/main/settings/settingsService.ts` 工厂 `createSettingsService(deps: { userDataDir })`（deps 注入便于测试）；`app.ts` 装配后注入 IPC。

## 6. 最小预览工作台（渲染层）

```text
src/renderer/src/features/
├── tree/          # 树面板：递归树（懒加载 listChildren）、点选文件、新建/删除入口
├── editor/        # 极简编辑区：textarea（M4 换 CodeMirror——与真编辑器同构：受控 value + 去抖写 + 保存事件），去抖写 + 保存钮
├── preview/       # PreviewPanel：iframe + 沙箱属性 + onVfsChanged 订阅重载（§4）
└── workspace/     # 三栏布局骨架：shell 插槽（§6.1）+ 选中态提升（最近公共父，宪法 A.7-6）
```

- 编辑区 textarea 为**占位实现**：其 props 面（`value/onChange/onSave/debounceMs`）按 M4 CodeMirror 真编辑器的最小接口定义，M4 替换实现不改 workspace（接缝）。
- 三栏固定布局（折叠/记忆归 M4，裁决 D5）。
- 树最小操作集（支撑 E2E 主链路）：新建文件/新建目录（父 = 当前选中目录或根）、删除（trash，不进回收站 UI）、点选文件。重命名/移动等完整操作归 M4。
- 编辑区：加载选中文件内容（`vfs:read`）→ textarea 受控；输入 → 去抖 → `vfs:write`；保存钮/Ctrl+S 预留（M4 菜单接管快捷键，M3 仅按钮）。二进制 MIME 文件只读展示元信息（不做编辑；图片等系统组件展示归 FR-EDIT-04 P1 后置）。
- 渲染端禁止感知通道字符串与 ipcRenderer（A.7-4），全部经 `window.api` 类型化桥（preload 追加 `settingsGet`/`settingsSet` 具名包装）。

### 6.1 三栏 shell 插槽（用户评审接缝要求）

workspace 顶层组件以**插槽 props** 定义外壳边界：`toolbarSlot`（M4 原生菜单的渲染层对应面/全局操作条）、`treeSlot`/`editorSlot`/`previewSlot` 三面板各由独立组件注入、`statusBarSlot`（M4+ 预留）。布局参数（宽度比例、折叠态）在组件 state 内为 M4 记忆化留接口位（M3 仅常量默认值）。M4 外壳批次往插槽填内容，不重排 workspace 结构。

## 7. P1 协议级设计（实现后置，登记 TASK.md）

### 7.1 DevTools（FR-RENDER-05）

采用主 `webContents.inspectElement(x, y)`（Electron 原生，自动定位到命中位置的子 frame，含沙箱 iframe）——预览区右键菜单项「检查元素」触发；不做独立 DevTools 窗口托管。M4 与编辑器右键菜单同批实现。

### 7.2 滚动同步（FR-RENDER-06，双向）

- 协议：父→子 `postMessage({ type: 'lt:scroll-ratio', ratio })`；子→父 `postMessage({ type: 'lt:scroll-report', ratio, anchorText })`，消息仅含比例与锚点文本（无 Node 能力，opaque origin 下唯一通道）。
- 行级锚点策略：通用 HTML 无行语义，采用「编辑器可视首行 → 比例映射 + 就近文本锚点校正」启发式；`pre`/`code` 元素内按行精确映射。局限（启发式在复杂布局下的偏差）定档为 P1 已知边界，不追求像素级。
- 依赖 M4 编辑器行号模型，实现归 M4 联动批次。

### 7.3 CSS 热替换（FR-RENDER-07）

- 触发：`onVfsChanged` 收到 `written` 且变更节点 MIME 为 `text/css` 且当前预览文档引用了该路径。
- 动作：父层 `fetch(vfs://该路径)` 拿新文本（`connect-src vfs:` 已为此开通）→ `postMessage({ type: 'lt:css-swap', href, text })` → iframe 内联接收器替换对应 `<link>` 为等值 `<style>`——滚动位置天然保持。
- 接收器由协议层对 `text/html` 响应做**只读注入**（`</body>` 前插入固定接收器 `<script>`，不修改库内 BLOB、不破坏 content_hash 与 ETag 的一致性语义——注入在响应构造期完成）——M3 不实现，但注入点与消息协议本 spec 定死，M4 直接实现不返工。

## 8. 错误处理与日志

- 协议层：404/416 固定短语响应（§2.2/§2.3）；handler 意外异常 → 500 固定短语 + error 日志（含堆栈）。
- settings：载荷非法 → `E_IPC_BAD_PAYLOAD`（既有码）；文件损坏/schemaVersion 不识别 → 回退默认值 + warn（§5）。
- 渲染层：写失败/读失败经 Result 的用户可读 message 呈现（docs/03 §2.3 toast 策略，M3 以编辑区/预览区行内提示替代完整 toast 组件——toast 归 M4 外壳）。
- 日志纪律：info 记 settings 变更（键+新值）；协议 handler 高频请求不记 info（§2.6）。

### 9.1 验收关键项（用户评审点名）

1. **路径解析三形态**：相对（`./style.css`、`img/a.png`）、根相对（`/笔记/x.css`）、绝对（`vfs:///笔记/web/x.css`）均正确落到 VFS 子树并带正确 MIME。
2. **`../` 越界 404**：解码后含 `..`/`.`/空段的请求一律 404，无 clamp、无信息泄露。
3. **内联 script 可执行**：文档内 `<script>` 正常运行（`'unsafe-inline'` + `allow-scripts` 组合）。
4. **预览内 fetch（null origin）**：沙箱文档 `fetch('vfs:///笔记/data.json')` 带 `Origin: null` → CORS 通配头放行成功；`fetch('https://…')` 被 CSP 阻断。
5. **连续输入最终态一致**：高频输入（短于去抖间隔）停止后，预览内容与编辑终态逐字符一致（防撕裂协议生效）。
6. **重载只有变更文件回 200**：编辑主文档保存后重载，监听网络——主文档/变更资源 200、未变子资源 304（ETag revalidate 生效）。
7. **localStorage 抛异常**：文档内访问 `localStorage` 抛 SecurityError——隔离断言（已知边界，§3.1）。

覆盖率门禁沿用 A.6-3（新目录 `src/main/settings/**`、`src/main/protocol/vfsProtocol.ts`、`src/shared/settings-contract.ts` 计入核心 100%）。
