## 1. 定位与交付边界

M3 交付「浏览器级保真实时预览」的完整管线：`vfs://` 自定义协议（SQLite BLOB → HTTP 语义响应）、沙箱 iframe 与 CSP、实时刷新链路（去抖 → 写 → 事务提交 → 广播 → 重载）、最小设置通道、承载上述能力的**最小预览工作台 UI**，以及 E2E 主链路验证。

**纳入范围（P0，M3 实现）**：FR-RENDER-01/02/03/04 + NFR-04 + FR-SHELL-01 的「三栏」静态骨架（不含折叠/记忆）。

**设计纳入、实现后置（P1）**：FR-RENDER-05 DevTools、FR-RENDER-06 滚动同步、FR-RENDER-07 CSS 热替换——本 spec 给出协议级设计（§7），实现归 M4/M5 批次（登记 TASK.md）。

**不在范围**：FR-SHELL-01 的可折叠与布局记忆、FR-SHELL-02 原生菜单与快捷键（归 M4 外壳批次，与编辑器同批验收）；FR-AUX-03 完整设置页（M5，M3 仅落 §5 最小设置通道）；Markdown 渲染（`.md` 按浏览器语义由 M4+ 决定是否加渲染管线，M3 按 text/plain 呈现即保真）。

## 2. vfs:// 协议设计

### 2.1 URL 身份结构（裁决 D1：路径式）

`vfs://` URL 以**虚拟路径**为身份：`vfs:///笔记/web/index.html`。iframe src 直接使用虚拟路径，相对资源引用（`./style.css`、`img/a.png`、`../共享/x.js`）由 Chromium 标准 URL 解析落在同一 VFS 子树——与系统浏览器以 `file://` 打开同目录文档的行为同构（FR-RENDER-01/02 保真来源），docs/03 §2.2-3「无需改写用户 HTML」由此成立。

- 被否方案：id 基式（`vfs://n5/index.html`）——rename/move 后 URL 不失效，但相对解析后 id 与名字混合、用户 HTML 绝对路径引用需兼容层，保真度受损。
- rename/move 后旧 URL 失效是浏览器同款行为；刷新链路由渲染层持有 nodeId、重载前经 `resolvePath` 语义（§4.3）取最新路径，自然落新地址。

### 2.2 路径解析语义

1. handler 只接受 path 部分；query string **忽略**（不参与身份，预留缓存破坏用途不作依赖），fragment 忽略。
2. 逐段 `decodeURIComponent` 后按 `/` 连接还原虚拟路径；**禁止整串 decode 后再分段**（编码后的 `/`（`%2F`）不得充当路径分隔符——先按原始 `/` 分段，再逐段解码）。
3. 归一化拒绝：解码后任一段为空、`.`、`..`，或多重斜杠产生的空段——整条请求 404。库内 `virtual_path` 本身无这些形态，匹配天然安全（FR-RENDER-04「无法逃逸 VFS 之外」：解析只查 `node` 表，无文件系统接触）。
4. 查询条件：`virtual_path = ? AND deleted_at IS NULL`（活行；回收站资源不可达）。命中 `node_type = 'file'` 才响应，目录请求 404（`vfs://` 是资源出口，非列表出口）。
5. 解析不到活行 → 404，响应体不含任何库内信息（不泄露路径/表结构，B.5-2 同款纪律）。

### 2.3 响应语义

| 项 | 语义 |
| --- | --- |
| Content-Type | `mime.ts` 的 `lookupMimeType(fileName)`（M1 既有表，M1 注释已声明 M3 共用）；未识别回退 `application/octet-stream` |
| ETag | `W/"<content_hash>"` 弱校验器——content_hash 由 createNode/writeFile 写路径维护（M1 既有列），响应构造零 BLOB 读取；请求头 `If-None-Match` 匹配 → 304 无体 |
| Cache-Control | `no-cache`（每次使用前必须 revalidate，配 ETag 304 节流——刷新链路靠 iframe 重载发起，不强缓存保证写后可见） |
| Content-Security-Policy | 仅 `text/html` 响应注入（§3.2 值）；其余 MIME 不注入 |
| Accept-Ranges / 206 | `bytes`；`Range: bytes=start-end` 单区间 → 206 + `Content-Range: bytes start-end/total`，body 为 Buffer 切片（`Buffer.subarray`，零拷贝语义）；语法非法或越界 → 416；**多区间不支持 → 忽略 Range 头按 200 全量**（RFC 7233 允许） |
| HEAD | 与 GET 同头无体（健全性） |
| 416/404 响应体 | 固定短语（如 `Range Not Satisfiable` / `Not Found`），不含库内细节 |

### 2.4 实现形态

`src/main/protocol/vfsProtocol.ts` 导出 `handleVfsResource(request: Request): Promise<Response>`（与 appProtocol 同构签名）；BLOB 读取经存储层**同步短临界区**单行 `SELECT content FROM node ...`（宪法 A.1-7 允许；预览加载属用户显式导航，非批量路径）。装配在 `app.ts`：`protocol.handle('vfs', handleVfsResource)`，与协议注册顺序一致（B.3-1）。方案声明：`registerSchemesAsPrivileged` 若需 `standard: true` / `supportFetchAPI` / `stream` 属性（standard 是相对 URL 解析与百分比编码规范化的前提）在 M3 计划实测定值——此为 TASK.md「protocol.handle API 细则」调研项的收口，计划阶段以最小探针核实后落死。

### 2.5 日志取舍

协议 handler 高频（一个文档 = 主文档 + N 资源请求）：200/304/206 **不记日志**（全局 §二「禁止循环内大量日志」；资源加载失败由 iframe 内浏览器控制台呈现，FR-RENDER-02 明示）；仅 handler 意外异常记 error（含堆栈与 URL path）。

## 3. 沙箱与 CSP

### 3.1 iframe 沙箱属性（渲染层 PreviewPanel）

```html
<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" src="vfs:///笔记/web/index.html" />
```

- `sandbox="allow-scripts"` 且**不含** `allow-same-origin`：文档为 opaque origin——cookie/localStorage/DOM 存储禁用、XHR/fetch 同源能力禁用、表单提交/弹窗/顶层导航全禁（对应 token 不给）。脚本可运行（HTML 生态常态，保真），但拿不到任何敏感能力。
- `referrerpolicy="no-referrer"`：资源请求不携带引用来源。
- 父子通信（P1 滚动同步/热替换预埋）：仅 `postMessage`，opaque origin 下 targetOrigin 用 `*` 收发（内容无敏感能力，消息协议见 §7）。

### 3.2 CSP 值（裁决 D2：断外链）

仅对 `text/html` 响应注入：

```text
Content-Security-Policy:
  default-src 'none';
  script-src vfs: 'unsafe-inline';
  style-src vfs: 'unsafe-inline';
  img-src vfs: data: blob:;
  font-src vfs: data:;
  media-src vfs: data: blob:;
  object-src 'none';
  frame-src 'none';
  connect-src;
  form-action 'none';
  base-uri vfs:
```

- 资源仅可来自 `vfs:`（断 http/https 外链）——用户库中 HTML 成为本机数据的出网面被关闭（B.5-3 受限 CSP + 最小权限）；引用 CDN 的文档预览中 broken 是既定取舍（裁决 D2），下载入库即可恢复。
- `connect-src`（空值）断 fetch/XHR/EventSource/WebSocket；`frame-src 'none'` 禁嵌套 iframe；`object-src 'none'` 禁插件；`base-uri vfs:` 防 `<base>` 劫持相对解析；`form-action 'none'` 禁表单外发。
- `'unsafe-inline'`（script/style）：真实世界 HTML 大量依赖内联脚本与样式，禁用即破坏保真；其风险由 opaque origin（无同源权、无存储）+ 断网（无外发通道）兜底，剩余面与「以系统浏览器打开同一文档」一致。

## 4. 实时刷新链路

### 4.1 时序（与 docs/03 §2.2-4 一致）

```text
编辑器输入 → 渲染层去抖（preview.debounceMs，默认 300ms，FR-RENDER-03 可配置 100–2000）
  → vfs:write IPC → 主进程事务（内容+FTS 同事务，一致性红线）→ 提交成功
  → 广播 vfs:changed { type: 'written', node }（宪法 B.3-4，事务提交后）
  → PreviewPanel 收到广播且 node.id 匹配当前预览节点 → iframe 重载（新 ETag → 200 新内容或 304 判定）
```

- 「刷新仅发生在事务提交之后」由广播时序天然保证（广播在事务提交后发出，M1 已落地，B.3-4）。
- **保存动作立即刷新**：保存 = 立即发起 `vfs:write`（绕过/清空去抖计时器），广播到达后同样按上述链路重载。
- 去抖在**渲染层**（写之前），主进程不做去抖；去抖期间再次输入重置计时器（尾沿触发）。

### 4.2 重载语义

PreviewPanel 重载 = 重新赋值 `iframe.src` 为当前预览路径（路径来自选中节点实时解析，见 §4.3）；Chromium 对同 URL 发起导航时带 `If-None-Match`，内容未变时 304 短路、变更时 200 新体——写后必变 `content_hash`，无脏缓存窗口。

### 4.3 选中态与路径解析

工作台持有选中节点 `nodeId`；每次重载前以 `resolvePath`（M1 通道）反查当前 `virtual_path`——**不缓存路径**，rename/move 后第一次刷新即落新路径；`resolvePath` 失败（节点被 trash/purge）→ 预览区显示占位态（「文档不可用」），不重载旧内容。树刷新监听 `onVfsChanged` 全量事件（M1 广播），按事件形态做最小树同步（created/restored 增量插入、trashed/purged 移除、renamed/moved/written 刷新对应节点元数据）。

### 4.4 NFR-04 验收

「去抖到期后到预览完成重载 < 300ms（普通文档）」：本地路径 `vfs:` 加载 + BLOB 单行读 + 304/200 响应，链路无跨进程往返之外的开销；E2E 以宽松上限断言（集成测不出渲染重载真实耗时），实测值回填 TASK.md。

## 5. 最小设置通道（裁决 D4：M3 落地）

- 通道：`settings:get`（无参）→ `Result<SettingsData>`；`settings:set`（入参全量 `SettingsData`，渲染端 get→merge→set，避免 partial merge 语义）→ `Result<SettingsData>`。命名遵 B.2-5（docs/03 §7.1 既有通道名）。
- 契约单一来源：`src/shared/settings-contract.ts`——`SettingsSchema = z.strictObject({ preview: z.strictObject({ debounceMs: z.number().int().min(100).max(2000) }) })`；`SettingsData = z.infer<...>`；M5 完整设置页在此 schema 上扩展键。校验失败映射 `E_IPC_BAD_PAYLOAD`，**不新增错误码**。
- 存储：`app.getPath('userData')/settings.json`（宪法 A.2-1），主进程独占读写；启动读一次进内存缓存，`set` 时先 zod 解析再**原子写**（写临时文件 + rename），损坏/缺失/解析失败一律回退默认值（300ms）并 warn——用户数据不因设置文件损坏而阻断启动（fail-fast 仅适用于数据库，不适用于可丢弃的设置缓存）。
- 主进程服务：`src/main/settings/settingsService.ts` 工厂 `createSettingsService(deps: { userDataDir })`（deps 注入便于测试）；`app.ts` 装配后注入 IPC。

## 6. 最小预览工作台（渲染层）

```text
src/renderer/src/features/
├── tree/          # 树面板：递归树（懒加载 listChildren）、点选文件、新建/删除入口
├── editor/        # 极简编辑区：textarea（M4 换 CodeMirror），去抖写 + 保存钮
├── preview/       # PreviewPanel：iframe + 沙箱属性 + onVfsChanged 订阅重载
└── workspace/     # 三栏固定布局骨架 + 选中态提升（最近公共父，宪法 A.7-6）
```

- 三栏固定布局（可折叠与记忆归 M4，裁决 D1 之外的 M3 边界裁决）；状态提升：选中 nodeId 在 workspace 持有，tree/editor/preview 经 props/onXxx 消费（A.7-6）。
- 树最小操作集（支撑 E2E 主链路）：新建文件/新建目录（父 = 当前选中目录或根）、删除（trash，不进回收站 UI）、点选文件。重命名/移动等完整操作归 M4。
- 编辑区：加载选中文件内容（`vfs:read`）→ textarea 受控；输入 → 去抖 → `vfs:write`；保存钮/Ctrl+S 预留（M4 菜单接管快捷键，M3 仅按钮）。二进制 MIME 文件只读展示元信息（不做编辑，图片等系统组件展示归 FR-RENDER/EDIT P1 后置）。
- 渲染端禁止感知通道字符串与 ipcRenderer（A.7-4），全部经 `window.api` 类型化桥（preload 追加 `settingsGet`/`settingsSet` 具名包装）。

## 7. P1 协议级设计（实现后置，登记 TASK.md）

### 7.1 DevTools（FR-RENDER-05）

采用主 `webContents.inspectElement(x, y)`（Electron 原生，自动定位到命中位置的子 frame，含沙箱 iframe）——预览区右键菜单项「检查元素」触发；不做独立 DevTools 窗口托管。M4 与编辑器右键菜单同批实现。

### 7.2 滚动同步（FR-RENDER-06，双向）

- 协议：父→子 `postMessage({ type: 'lt:scroll-ratio', ratio })`；子→父 `postMessage({ type: 'lt:scroll-report', ratio, anchorText })`，消息仅含比例与锚点文本（无 Node 能力，opaque origin 下唯一通道）。
- 行级锚点策略：通用 HTML 无行语义，采用「编辑器可视首行 → 比例映射 + 就近文本锚点校正」启发式；`pre`/`code` 元素内按行精确映射。局限（启发式在复杂布局下的偏差）写入 spec 即定档为 P1 已知边界，不追求像素级。
- 依赖 M4 编辑器行号模型，实现归 M4 联动批次。

### 7.3 CSS 热替换（FR-RENDER-07）

- 触发：`onVfsChanged` 收到 `written` 且变更节点 MIME 为 `text/css` 且当前预览文档引用了该路径（重载前由父层比对当前文档 URL 与引用收集结果）。
- 动作：父层 `fetch(vfs://该路径)` 拿新文本 → `postMessage({ type: 'lt:css-swap', href, text })` → iframe 内联脚本（随文档注入的接收器）查找对应 `<link>` 替换为等值 `<style>` 或更新 href 带缓存破坏参数——滚动位置天然保持。
- 需文档内预置接收器脚本：由协议层对 `text/html` 响应做**只读注入**（在 `</body>` 前插入固定接收器 `<script>`，不修改库内 BLOB）——M3 不实现，但该注入点在本 spec 定死，避免 M4 返工协议头格式。

## 8. 错误处理与日志

- 协议层：404/416 固定短语响应（§2.2/§2.3）；handler 意外异常 → 500 固定短语 + error 日志（含堆栈）。
- settings：载荷非法 → `E_IPC_BAD_PAYLOAD`（既有码）；文件损坏回退默认值 + warn（§5）。
- 渲染层：写失败/读失败经 Result 的用户可读 message 呈现（docs/03 §2.3 toast 策略，M3 以编辑区/预览区行内提示替代完整 toast 组件——toast 组件归 M4 外壳）。
- 日志纪律：info 记 settings 变更（键+新值，不含敏感）；协议 handler 高频请求不记 info（§2.5）。
