## 2. 保存管线（docs/07 核心决策域）

### 2.1 单写管线双计时器（裁决 D2）

编辑变更只有一个落库出口，两个计时器协同：

| 计时器 | 参数 | 触发 | 语义 |
| --- | --- | --- | --- |
| 尾沿去抖 | `preview.debounceMs`（既有，100–2000 默认 300） | 输入停顿 | FR-RENDER-03 原语义：停顿即写，写提交即刷新预览 |
| 最长挂起 | `editor.autoSaveMs`（新增，1000–60000 默认 3000） | 连续输入不停顿 | FR-EDIT-02「自动保存间隔默认 3s 有改动即存」的精确语义 = **最长相邻自动写间隔**——连续打字永不触发尾沿时，挂起满 3s 强制落库一次 |

- 两计时器共用同一脏缓冲：任一到期即 flush 当前 doc 快照，另一计时器随后归零重算。Ctrl/Cmd+S = 立即 flush 并清双计时器（无选中标签 / 非文本标签 no-op）。
- **为什么不是两条独立管线**：FR-RENDER-03 的「停顿 300ms 刷新」要求写库在先（刷新因果链 = 事务提交后广播，M3 §4.1），若 3s 自动保存是第二条写路径，同一文件会出现两个写者，合并语义复杂化且无业务收益——docs/03 的两个参数在本设计中是**同一管线的两个约束**（节奏与上限），非两个功能。

### 2.2 写合并与竞态规则（裁决 D2 附则）

1. **同标签页写串行**：同一 nodeId 同时最多一个在途 `vfs:write`；在途期间的新变更标记 `pendingDirty`，在途完成后若 dirty 则按 §2.1 双计时器重新调度。禁止并发写同文件（服务层覆盖写无版本比对，并发会乱序落库）。
2. **快照写**：flush 发起时取当时 doc 全文快照编码入参；在途写不感知后续输入——最终一致性由「后继写总会携带最新全文」保证（覆盖写语义下最后写者胜，且每次都是全文）。
3. **写失败**：保留 dirty，编辑区 notice 提示既有；按 `autoSaveMs` 周期自动重试（不自旋），期间新输入照常重置尾沿计时器。
4. **自写广播不回环**：`written` 广播仅驱动预览刷新（M3 §4 语义），编辑器 doc 不因广播回写重置——当前应用无第二写者，无外部冲突合并需求（YAGNI；导入覆盖同库场景归 M5 导入批次再评估）。
5. **切换/关闭标签**：切换标签不打断写管线（dirty 随标签走，后台标签照常落库）；关闭标签先同步 flush（清计时器发写），flush 失败（含节点已删）→ 确认放弃后关闭。
6. **节点被 trash/purge**：对应标签先尝试 flush（可能失败——节点已软删），随后关闭标签并清除选中态（E2E 主链路「删除」步骤的现状语义保持）。

### 2.3 脏标记与 unsaved-guard（裁决 D3）

- **dirty 定义**：标签存在未落库变更（去抖/挂起计时中、在途写后的 pendingDirty、或最近一次写失败未重试成功）。落库成功即清。
- **关闭窗口**：主进程 `win.on('close')` 拦截——首次 close 一律 `preventDefault` 并向渲染层发 `{ type: 'confirm-close' }` 命令；渲染层判定无脏标签 → 直接调 `shell:force-close`（invoke 通道，主进程置放行标记后 `win.close()` 放行）；有脏标签 → `window.confirm('有未保存的更改，确定退出？')`，确认 = 调 `shell:force-close` 放行并放弃挂起变更（挂起窗口 ≤ autoSaveMs，丢失面有界；异步 flush 在关窗路径不可靠，不做），取消 = 留在应用。**选型理由**：Electron 的 `beforeunload` returnValue 弹窗为原生消息盒，Playwright `_electron` 不可驱动（E2E 无法验收），`window.confirm` 可被 `page.on('dialog')` 驱动；无脏时首次 close 的拦截-直放行为对用户无感。**首日探针项**：close 拦截 + force-close 放行链路实测。
- **M3 遗留「卸载悬挂写」随此收口**：悬挂写本就是 dirty 态，guard 覆盖；关窗前不做异步 flush。
- 关闭标签页不弹 guard（§2.2-5 flush 后关，失败才确认）——自动保存架构下「脏但可静默丢弃」的窗口有界且可 flush，逐标签弹窗是打扰。

### 2.4 大文件阈值（裁决 D7）

| 体积（meta.size） | 行为 |
| --- | --- |
| ≤ 5MB | 直接打开（FR-EDIT-01 验收：打开 < 1s，E2E 计时） |
| 5–50MB | 原生 confirm 提示「大文件打开可能卡顿」后打开；不做只读模式（YAGNI） |
| > 50MB | 拒绝打开提示（与写侧 `E_VFS_FILE_TOO_LARGE` 对齐；渲染层以 meta.size 前置判定，不发起 readFile） |

## 3. 多标签页状态模型（FR-EDIT-03，裁决 D1 附则）

- `tabs: readonly TabState[]` + `activeTabId: number | null`；`TabState = { meta: NodeMeta; dirty: boolean }`。同文件唯一实例：重复点选/快速打开聚焦既有标签。
- 每标签持独立 CodeMirror `EditorState`（doc、selection、撤销历史随 state 天然保留）；切换 = `EditorView.setState(state)`（不重建 view，宪法 A.1-9 只经 dispatch/setState）；滚动位置 per-tab 自存自恢复（view 切换前读、切换后写回）。
- 关闭激活标签 → 激活右邻，无右邻激活左邻，全关 → 空态；同开上限 20（超限提示先关，防失控护栏）。
- TabBar：文件名 + dirty 圆点 + 关闭钮，`aria` 规范同 M3 树（role/button + aria-current）。
- rename/move 后标签标题随 meta 刷新（§6.3 同步链），tab 与 nodeId 绑定不与路径绑定。

## 4. CodeMirror 6 封装层（FR-EDIT-01/03）

- **包基线（2026-09-18 registry 实查，精确小版本计划期 lock）**：`codemirror` 元包不引入——curated 扩展集自组：`@codemirror/state 6.7.5`、`@codemirror/view 6.43.12`、`@codemirror/commands 6.11.1`、`@codemirror/language 6.12.4`、`@codemirror/search 6.7.2`、`@codemirror/lang-html 6.4.12`、`@codemirror/lang-css 6.3.1`、`@codemirror/lang-javascript 6.2.5`。
- **扩展集（裁决 D6，curated 不引元包 basicSetup）**：lineNumbers（滚动同步 §M3-7.2 的行号模型依赖）、history + historyKeymap、drawSelection、indentOnInput（自动缩进）、bracketMatching（括号匹配）、search + searchKeymap（查找替换 Ctrl/Cmd+F，P0）+ defaultKeymap + indentWithTab（Tab 缩进，Esc 逃出）。**不含** autocompletion、closeBrackets、foldGutter、activeLine、highlightSelectionMatches（未要求，YAGNI）。语法高亮走 `syntaxHighlighting(defaultHighlightStyle)`；暗色主题归 M5 设置页（FR-AUX-03）。
- **语言映射**（`language.ts` 纯函数，mime → LanguageSupport | null）：`text/html` → `html()`（内嵌 script/style 的 JS/CSS 解析随包内置）；`text/css` → `css()`；`text/javascript`/`application/javascript` → `javascript()`；其余文本（txt/json/xml/未知）纯文本无高亮。JSON/XML 高亮不在 FR-EDIT-01 字面（HTML/CSS/JS/TXT），不装 lang-json/lang-xml（YAGNI）。
- **封装习语**（宪法 A.1-9 + 调研 A7-10）：扩展工厂函数（静态扩展只建一次依赖去重）；文档变更只经 `view.dispatch`；换文档新建 `EditorState` 不复用；`view.destroy()` 释放成对。渲染层禁 import 主进程模块照旧（B.2）。
- **EditorPanel 换内核不改 props 面**：`{ node, debounceMs }` 不变；textarea → CodeMirror 容器 div；保存钮保留（快捷键之外可见入口）；二进制/空态分支保持（编辑能力判定 `isTextLike` 语义不变）。
- **IME 边界**：composition 期间 CodeMirror 的 updateListener 照常报 docChanged，写管线照常调度（尾沿 + 挂起上限保证 composition 长按时 3s 内强制落库；预览可能短暂显示拼音中间态——编辑器与预览分离，composition 不被打断，定档已知边界，计划期探针复核一次）。

## 5. 应用外壳

### 5.1 三栏折叠与记忆（FR-SHELL-01，裁决 D5）

- 每栏独立折叠切换（面板标题条折叠钮；折叠后留窄条展开钮）；树/预览两栏宽度可拖拽分隔条调整（编辑器栏自适应占余），比例约束 0.15–0.6 clamp。
- 布局状态持久化于 settings（§7 `shell.layout`），启动恢复；折叠组合无互斥（三栏可同时折叠）。
- 编辑器栏折叠时保存管线照常（写库与预览刷新不依赖可见性）。

### 5.2 原生菜单与快捷键（FR-SHELL-02，裁决 D5）

- 主进程 `Menu.buildFromTemplate`（M4 骨架一次到位，未落款项 disabled 占位，M5 往缝里填）：
  - **文件**：新建文件（Cmd/Ctrl+N）、新建目录（Cmd/Ctrl+Shift+N）、保存（Cmd/Ctrl+S）、分隔线、退出（role）；
  - **搜索**：快速打开（Cmd/Ctrl+P，disabled——M5 搜索 UI）、全局搜索（Cmd/Ctrl+Shift+F，disabled——同）；
  - **导入导出**：导入…/导出…（disabled——M5）；
  - macOS 增 app 菜单基本项（关于/退出）满足平台惯例；三平台菜单结构同一模板分支生成。
- **命令通道**：菜单点击 → 主进程 `webContents.send(IPC.shellCommand, ShellCommand)`；`ShellCommand` 为可辨识联合（`{ type: 'new-file' | 'new-dir' | 'save' | 'confirm-close' }`，shared `shell-contract.ts` 单一来源，B.2-5 命名 `shell:command`）；preload 暴露 `onShellCommand(callback): () => void` 包装（同 onVfsChanged 先例，禁透传原始回调）；渲染层 Workspace 订阅 dispatch（save → flush，new-file/new-dir → 复用树新建逻辑，confirm-close → §2.3 guard 确认链）。配套渲染→主 `shell:force-close`（invoke，无参：主进程置放行标记后 `win.close()`，guard 放行唯一通道）。
- 快捷键由菜单 accelerator 承载，渲染层不再自挂键盘监听（单一来源；编辑器内 Ctrl+F/Ctrl+Z 等编辑键位归 CodeMirror keymap，与菜单键位无交集，无冲突面）。

### 5.3 右键「检查元素」（FR-RENDER-05 DevTools，P1——裁决 D1）

- `webContents.on('context-menu')` → `Menu.popup`（仅一项「检查元素」）→ `contents.inspectElement(x, y)`（自动命中命中点所在的沙箱 iframe，M3 spec §7.1 已定）；全窗口生效不做区域细分（YAGNI）。

### 5.4 CSS 热替换（FR-RENDER-07，P1——裁决 D1）

按 M3 spec §7.3 已定协议实现：

- **接收器注入**（协议层）：`vfsProtocol` 对 `text/html` 响应在 `</body>` 前插入固定接收器 `<script>`（响应构造期完成，**不改库内 BLOB、不参与 content_hash/ETag**——hash 仍基于库内内容；注入对所有加载一致，无「同 hash 不同体」问题）。接收器监听 `message` 事件，收到 `{ type: 'lt:css-swap', href, text }` 将对应 `<link rel="stylesheet">` 替换为等值 `<style>`（滚动位置天然保持）。
- **触发**（渲染层）：`onVfsChanged` 收到 `written` 且 `event.node.mimeType === 'text/css'` 且该路径存在于当前预览文档引用中（简化判定：当前预览为 html 且引用了该 css 同目录/相对路径——首版按「预览激活且任一标签的 css 写入即尝试热替换」实现，替换失败静默回退整页刷新）→ `fetch(vfsUrl(path))` 拿新文本 → `iframe.contentWindow.postMessage({ type: 'lt:css-swap', ... }, '*')`（opaque origin，M3 §3.1 预埋语义）。
- **已知边界**：`@import` 二级引用不追踪；js 引用的 css 动态插入不覆盖；替换失败（link 不存在）静默忽略。

### 5.5 最小 toast（M3 spec §8 归属兑现）

## 6. M3 打磨批次收口（TASK.md「预览打磨批次」全项）

### 6.1 路径新鲜与占位态（spec §4.3 补实现）

- **新增 `vfs:get` 通道**（`nodeId → NodeMeta`，主进程单行 SELECT；M1 十通道无 id→meta 反查，rename/move 后取新路径需要它）。契约入 shared（`NodeMetaResponse`），preload/服务同批接线。
- **rename/move 后 meta 同步链**：广播 `renamed/moved` → 渲染层对受影响选中节点/打开标签 `vfs:get(nodeId)` 反查新 meta → 更新 `selected` 与 tabs（树侧既有 stale 重取链不变）→ PreviewPanel node prop 更新 → `key=url` 重挂落新路径。
- **重载前反查双保险**：PreviewPanel 收到命中 `written` 时先 `vfs:get(nodeId)`——失败（节点已删）→ 预览占位态「文档不可用」，不重载旧路径（M3 spec §4.3 语义兑现）。
- **PreviewPanel 订阅改挂载期一次**：`node` 经 effect 内同步的 `nodeRef`（effect 内写 ref 合法，75647f2 先例不禁）供订阅闭包比较，订阅 effect 依赖 `[]`——消除随 node 重建的退订/重订微窗口（终审 M-4）。

### 6.2 树重命名/移动 UI（FR-VFS-04/05 的渲染层入口）

- **重命名**：树工具栏「重命名」钮（有选中时）→ 行内模态（受控 input 预填当前名 + 确认/取消）→ `renameNode`；`E_VFS_DUPLICATE_NAME`/`E_VFS_INVALID_NAME` 经 toast 呈现，模态不关可改。
- **移动**：树工具栏「移动到…」钮 → 进入选择模式（状态条提示「在树中选择目标目录并确认」；此模式中 dir 点选临时变为「选定目标」高亮语义，file 点选禁用）→「确认移动」调 `moveNode`（`E_VFS_INVALID_MOVE` 前置校验：目标为自身/后代时禁用确认钮 + 提示）；Esc/取消退出模式。
- 根节点不可重命名/移动（M1 语义，UI 禁用入口）。

### 6.3 其余打磨项

- **text/* charset**（终审 M-5）：协议层 `Content-Type` 对 `text/*` 附加 `; charset=utf-8`（库内容恒 UTF-8 写入，docs/03 §3.2 语义对齐；修掉无 meta 非 ASCII 乱码），E2E 补头断言。
- **unsaved-guard 收口卸载悬挂写**：§2.3 已设计。
- M2 deferred 顺手清（TASK.md 触发条件「M4 触碰对应文件时」）：MatchIn 派生化、filterFragments 参数化、搜索测试细化、片段高亮码元——**仅 M4 确实触碰对应文件时执行，不主动扩面**。

## 7. 设置 schemaVersion 2（裁决 D4）

```ts
SettingsSchema = z.strictObject({
  schemaVersion: z.literal(2),
  preview: z.strictObject({ debounceMs: <既有 100–2000 默认 300> }),
  editor:  z.strictObject({ autoSaveMs: z.number().int().min(1000).max(60000) }), // 默认 3000
  shell:   z.strictObject({ layout: z.strictObject({
    treeCollapsed: z.boolean(), editorCollapsed: z.boolean(), previewCollapsed: z.boolean(),
    treeWidthRatio: z.number().min(0.15).max(0.6), previewWidthRatio: z.number().min(0.15).max(0.6),
  }) }),
});
```

- **迁移例程（M3 §5 预留接缝首次落地）**：服务启动读到 v1 文件 → 按默认值补 `editor`/`shell` 域 → 升 `schemaVersion: 2` → 原子回写 + info 日志一次；损坏/不识别版本（>2）→ warn 回退出厂默认（既有语义）。渲染端 `settingsGet` 恒得 v2 全量，无分支。
- 默认值：`editor.autoSaveMs = 3000`（FR-EDIT-02 字面）；布局默认全展开、`treeWidthRatio = 0.25`、`previewWidthRatio = 0.4`。
- `debounceMs` 语义不变；`autoSaveMs` 语义见 §2.1。

## 8. 错误处理与日志

- 不新增错误码：rename/move/create 复用 M1 既有码经 toast 直出；guard/确认框用原生 confirm（主窗口非沙箱，可用）；`shell:command` 为主→渲染命令（非 invoke），渲染层 switch + never 穷举兜底。

### 9.1 验收关键项

1. **E2E 主链路（docs/03 §6.2 M4 出口）**：新建目录→新建文件→编辑（自动保存落库）→预览一致→重命名→预览落新路径且标签标题刷新→移动→删除（标签关闭、预览占位）→桥还原→重新打开可编辑；搜索步骤经 `searchQuery` 桥命中并定位打开。
2. **保存管线**：连续输入超 3s 强制落库一次（autoSaveMs 语义）；停顿 300ms 落库（debounceMs 语义）；Ctrl/Cmd+S 立即落库。
3. **多标签**：双文件切换各保 doc/undo/光标；dirty 圆点随输入出现、落库消失；关闭激活标签右邻补位。
4. **折叠记忆**：折叠树栏 + 调宽度 → 重启（同 userData）→ 布局恢复。
5. **菜单命令**：原生菜单「保存」等效 Ctrl+S；disabled 项不可点。
6. **热替换**：编辑已引用 css → 预览无主文档重载（网络监听零主文档请求）且新样式生效（getComputedStyle 断言）。
7. **检查元素**：预览区右键 → 检查元素 → DevTools 已打开（`webContents.isDevToolsOpened()` 桥断言或可见性）。
8. **unsaved-guard**：dirty 时关窗弹原生确认（Playwright dialog 事件断言）；确认后退出。
9. **5MB 文档打开 < 1s**（计时中位回填）。

覆盖率门禁沿用 A.6-3：`src/main/menu/**` 入核心 100%（main 目录 glob 既有）；渲染层保存管线/tab 状态机纯函数以单测 100% 支撑全局线（与 M3 同口径，门槛 glob 不扩）。
