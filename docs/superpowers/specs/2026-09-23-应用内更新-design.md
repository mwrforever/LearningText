# 应用内更新设计（FR-UPDATE-01）

> 日期：2026-09-23 ｜ 批次：M9 ｜ 范围：主进程侧（能力判定 / 状态机 / electron-updater 适配 / IPC 四通道 / 装配与生命周期）
> 契约单一来源：`src/shared/update-contract.ts`（UpdateState 八态、UpdateCapability、UpdateRequestSchema）、`src/shared/ipc.ts`（通道常量）；本文只记设计决策与边界，不复制契约正文。
> 相关文件：`src/main/update/updateCapability.ts`、`src/main/update/updateService.ts`、`src/main/update/electronUpdaterAdapter.ts`、`src/main/ipc.ts`、`src/main/app.ts`、`electron-builder.yml`。

## 1. 范围与需求编号

- **FR-UPDATE-01 应用内更新**：打包形态下，应用可检查 GitHub Releases 上的新版本、经用户确认后下载、再次确认后重启安装；全程状态经 `update:state` 广播呈现于设置页。
- 本设计**只覆盖主进程侧**：能力判定、状态机服务、electron-updater 适配、四条 IPC 通道、装配与生命周期接线、打包发布配置。渲染层呈现（设置页 UI）见对应渲染层设计。
- 技术底座：`electron-updater@6.8.9`（已在 dependencies 锁定），GitHub Releases 作为发布源；更新检查元数据来自随包发布的 `app-update.yml`（由 `electron-builder.yml` 的 `publish` 段生成）。

## 2. 能力矩阵

能力判定为装配期纯函数 `resolveUpdateCapability`（输入：`app.isPackaged`、`process.platform`、`process.env.APPIMAGE`），不满足条件的形态**显式降级** `unsupported` 并携带原因，而非静默失败：

| 运行形态 | 判定输入 | 能力 | 原因 / 理由 |
| --- | --- | --- | --- |
| 开发形态（`electron .` 直启） | `isPackaged=false` | ❌ 关闭 | `dev`——无随包 `app-update.yml`，electron-updater 初始化即抛错；dev 分支优先于平台判定 |
| Windows NSIS 安装包 | `isPackaged=true, platform=win32` | ✅ 开启 | electron-updater 官方支持的替换路径（NSIS 静默安装） |
| macOS DMG（现状） | `isPackaged=true, platform=darwin` | ❌ 关闭 | `platform`——安装包未签名，Squirrel.Mac 替换阶段必须校验代码签名，未签名包替换必失败；签名链路落地前显式降级，禁止「下载完成后安装崩溃」的半途失败 |
| Linux AppImage | `isPackaged=true, platform=linux, APPIMAGE 非空` | ✅ 开启 | AppImage 单文件可就地替换（electron-updater 以 `APPIMAGE` 路径为替换目标） |
| Linux 解包目录 / deb / rpm | `isPackaged=true, platform=linux, APPIMAGE 空` | ❌ 关闭 | `platform`——Electron 仅在以 AppImage 启动时注入该环境变量，其余形态没有可就地替换的单一文件目标 |

## 3. 状态机（八态）

状态定义见 `UpdateState`（shared 单一来源）。状态机归属主进程服务，每次变更先记 info 日志（变更前后状态与版本号）再经 `onState` 推送。

| 当前态 | 事件 / 动作 | 次态 | 说明 |
| --- | --- | --- | --- |
| （初始，能力开启） | 服务创建 | `idle` | 渲染层经 `update:get-state` 首拉；初始态不广播 |
| （初始，能力关闭） | 服务创建 | `unsupported` | 携 `reason`，渲染层据此收敛更新入口 |
| `idle` / `up-to-date` / `error` / `available`(已完成) | `check()` / 周期检查触发 | `checking` | 能力关闭不发请求直接返回；checking 中重入返回当前态（防抖） |
| `checking` | `update-not-available` | `up-to-date` | `checkedAt` 取主进程本地 ISO 时刻 |
| `checking` | `update-available` | `available` | 记录新版本号供后续态复用 |
| `checking` | `error` / `checkForUpdates` reject | `error` | 检查失败不阻断主功能，周期检查自动重试；message 剥换行为单行 |
| `checking` | `checkForUpdates` resolve 且无任何结论事件 | `up-to-date` | **以事件为准、promise 兜底**：事件先到则事件态为准；promise 结束仍无事件按已检查兜底，保证 check() 必返回终态、状态机不滞留 checking |
| `available` | `download()` | `downloading` | percent 0 起；非 available 态调用为 no-op（防重复点击与非法态调用） |
| `downloading` | `download-progress` | `downloading` | percent 四舍五入取整并钳制 0–100，非有限数按 0 |
| `downloading` | `update-downloaded` | `downloaded` | 携新版本号 |
| `downloading` | `error` / `downloadUpdate` reject | `error` | 下载失败经 catch 收口，杜绝未处理 promise rejection |
| `downloaded` | `install()` | 进程退出 | 仅 downloaded 态执行 `quitAndInstall()`；其余态 no-op（非下载完成态调用会抛错或无意义） |

定时检查：`start()` 在窗口创建后调用——启动后 5s 首查（避开开库/建窗/首帧争抢），此后每 4 小时一次（`CHECK_INTERVAL_MS = 14_400_000`）；能力关闭不排任何定时器、不发任何网络请求。`dispose()` 成对释放两个句柄且幂等（`will-quit` 调用；服务未创建时可选链短路）。

## 4. 事件 → 状态映射

electron-updater 事件经 `UpdaterLike` 窄接口订阅（宽签名到窄签名的适配收敛在 `electronUpdaterAdapter` 一处）：

| electron-updater 事件 | 载荷（本服务消费字段） | 状态转移 |
| --- | --- | --- |
| `checking-for-update` | — | → `checking`（已在 checking 时同态去重，避免重复广播） |
| `update-available` | `version` | → `available`（记录 pendingVersion） |
| `update-not-available` | — | → `up-to-date`（checkedAt = 本地 ISO） |
| `download-progress` | `percent` | → `downloading`（钳制取整；版本号取 pendingVersion） |
| `update-downloaded` | `version` | → `downloaded` |
| `error` | `message` | → `error`（message 剥换行；error 留痕含原始异常） |

构造期一次性翻转 `autoDownload = false`、`autoInstallOnAppQuit = false`（先关自动行为再订阅，杜绝窗口期自动下载）——下载与安装必须经用户确认。

## 5. IPC 契约

四通道均无参（载荷 `null`，`UpdateRequestSchema = z.null()`，先例同 `settings:get`），均为状态机转发、无 vfs 写事务 → 不广播 `vfs:changed`（宪法 B.3-4）：

| 通道 | 包装 | 语义 |
| --- | --- | --- |
| `update:get-state` | `handleWith` | 读当前状态（渲染层挂载期首拉） |
| `update:check` | `handleWithAsync` | 立即检查；返回本次检查的终态（能力关闭/checking 重入返回当前态） |
| `update:download` | `handleWith` | 开始下载；同步返回 downloading 新态（进度经广播到达） |
| `update:install` | `handleWith` | 重启安装；响应 `null`（调用后进程即将退出，续体可能不落地） |

主→渲染广播：`update:state`（`onState` 供给，app 层遍历全部窗口 `webContents.send`）。该广播与 `vfs:changed` 同型广播面，但**不属于事务广播**——更新状态无写事务，推送时机 = 服务状态机每次变更。

## 6. 安全与隐私

- **网络面最小化**：仅访问 `app-update.yml` 指向的 GitHub Releases 公开元数据与安装包下载 URL（HTTPS）；无遥测、无统计上报、无任何用户数据出站。
- **无凭据**：更新检查为公开仓库匿名读取，不内嵌 GitHub token；私有仓库化后需另行评审（届时 token 属敏感值，禁入 `VITE_*`，宪法 A.2-3）。
- **完整性**：electron-updater 校验安装包 sha512（latest.yml 元数据）后再执行替换；`update:install` 仅在 downloaded 态触发，无渲染层可伪造的安装入口。
- **进程边界**：electron-updater 运行于主进程，不向渲染层暴露其实例（preload 只见四通道 + 状态广播）。

## 7. 不做什么（范围收敛）

- **不做全自动静默安装**：下载与安装均需用户确认（关闭 `autoDownload` / `autoInstallOnAppQuit`）。
- **不做增量差分**：electron-updater 的 blockmap 差分下载不作为承诺项，整包下载为基线行为。
- **不做 beta 通道 / 更新设置项**：单一 stable 通道，无「允许预发布版本」开关。
- **不做 macOS 自更新**：签名链路落地前 darwin 恒 unsupported（见能力矩阵）。
- **不做强制更新**：不阻塞主功能，error 态仅呈现、周期检查自动重试。

## 8. 风险与排查

- **SmartScreen 提示**：Windows 安装包未签名，用户首次安装（及每次更新安装）可能触发 SmartScreen/未知发布者提示——属预期摩擦，签名证书落地前无法消除；文档与发布说明需给「更多信息 → 仍要运行」指引。
- **draft 未发布前不可见**：Release 工作流产 draft、人工闸门后发布；draft 状态下用户端检查不到新版（GitHub 不对匿名请求暴露 draft 资产）。若「发布后仍查不到」，先确认 Release 已从 draft 转为 published。
- **CI 产物漏上传 `latest.yml`**：更新检查依赖 latest.yml（版本号 + sha512 + 下载 URL）；若检查失败且日志报 404 / manifest 解析错误，按以下路径排查：
  1. 确认 Release 工作流产物包含 `latest.yml`（Windows NSIS 形态）且已随 Release 上传；
  2. 确认 `electron-builder.yml` 的 `publish` 段与 CI `--publish always` 的 owner/repo 一致（双写漂移会导致 app-update.yml 指向错误仓库）；
  3. 本地打包冒烟可检查 `release/` 下是否生成 `app-update.yml`（缺失即 publish 段未生效）。
- **时序兜底**：electron-updater 的 promise resolve 与终端事件到达顺序无契约保证，状态机以「事件为准、promise 兜底」收敛（§3），避免渲染层滞留 checking。

## 9. 必须真机验证的项（打包形态，单测不可替代）

1. **打包版检查到新版**：以 `npm run package` 产出的 NSIS 安装包装机，本地起一个 published 的较低版本 Release（或临时调高线上版本号），启动应用 5s 后设置页出现「发现新版本 X.Y.Z」；`update:get-state` 与广播状态一致。
2. **确认下载**：点击下载后状态经 downloading（percent 推进）到 downloaded；下载期间关闭网络验证 error 态呈现与周期重试。
3. **重启安装**：downloaded 态点击安装后进程退出、新版本静默完成 NSIS 替换并重启；重启后版本号为新版本，数据目录与设置完整保留。
4. **AppImage 抽验**（Linux 真机）：AppImage 形态重复 1–3；解包目录形态确认入口按 unsupported 收敛。
