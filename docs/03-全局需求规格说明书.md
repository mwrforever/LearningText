## 1. 引言

### 1.1 目的

定义 LearningText 桌面应用的功能模块边界、总体架构、数据模型、功能需求（FR）与非功能需求（NFR），作为设计评审、实现、测试与验收的统一依据。

### 1.2 范围

覆盖 MVP（P0）与首个正式版（P1）的全部模块；P2 项仅声明预留点，不展开设计。

### 1.3 术语表

| 术语 | 定义 |
| ---- | ---- |
| VFS | 虚拟文件系统（Virtual File System），本应用中以 SQLite 为底层自建的文件树抽象层 |
| 节点 | VFS 树中的目录或文件的统称 |
| 虚拟路径 | 节点在 VFS 树中的绝对路径，如 `/笔记/web/index.html`，根为 `/` |
| `vfs://` | 应用自定义 URL 协议，用于渲染层按虚拟路径加载 VFS 资源 |
| FTS5 | SQLite 全文检索扩展（第 5 版），本项目使用其 trigram 分词器 |
| 主进程/渲染进程 | Electron 进程模型的两个组成部分 |
| 回收站 | 软删除节点的暂存区，节点带 `deleted_at` 时间戳即视为在回收站 |

### 1.4 运行环境

| 项 | 要求 |
| ---- | ---- |
| Windows | Windows 10 x64 及以上 |
| macOS | macOS 12 Monterey 及以上（Intel/Apple Silicon） |
| Linux | Ubuntu 22.04 及以上或等效 glibc 发行版，x64 |
| 数据位置 | 各 OS 标准用户数据目录（Windows `%APPDATA%`、macOS `~/Library/Application Support`、Linux `~/.config`） |

## 2. 总体架构

### 2.1 架构图

```text
┌─────────────────────────────── Electron 应用 ────────────────────────────────┐
│  渲染进程（React + CodeMirror 6｜contextIsolation + sandbox，无 Node 权限）    │
│  ┌────────────┐ ┌────────────┐ ┌────────────────┐ ┌───────────────────────┐  │
│  │ 资源树/搜索  │ │ 编辑器(M5) │ │ 预览控制(M4 UI) │ │ 沙箱 iframe（渲染区）  │  │
│  └─────┬──────┘ └─────┬──────┘ └───────┬────────┘ └───────────┬───────────┘  │
│        └──────────────┴───────┬────────┴──────────────────────┘              │
│                     类型化 IPC（contextBridge + zod 校验）                     │
├──────────────────────────────── 主进程 ───────────────────────────────────────┤
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────────┐    │
│  │ VFS 服务  │ │ 搜索服务  │ │ 导入导出  │ │ 设置服务  │ │ 备份/迁移服务     │    │
│  │  (M3)    │ │  (M6)    │ │  (M7)    │ │  (M8)    │ │  (M2)            │    │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘ └────────┬─────────┘    │
│       └────────────┴─────┬──────┴────────────┴───────────────┘              │
│                          ▼                                                  │
│              SQLite 单库（WAL 模式 + FTS5 trigram + BLOB 内容）               │
│  protocol.handle('vfs://') ← 预览与导入导出的资源读取通道                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 关键机制

1. **单一数据源**：SQLite 数据库文件是用户数据的唯一载体；"单文件即全部数据"，拷贝该文件即完成备份。
2. **主进程独占存储**：数据库只允许主进程访问（单连接、串行事务），从根上避免并发写冲突。
3. **`vfs://` 协议**：主进程把虚拟路径映射为 BLOB 流式响应（带 `Content-Type`、`ETag`）；预览 iframe 中 HTML 的相对资源引用由 Chromium 标准 URL 解析自动落在同一 VFS 子树，无需改写用户 HTML。
4. **实时预览链路**：编辑器变更 → 去抖（默认 300ms）→ IPC 写 VFS（事务提交）→ 主进程通知渲染进程 → 沙箱 iframe 重载目标文档。事务提交成功是刷新的前置条件，保证预览内容与库内数据一致。
5. **一致性红线**：任何 VFS 树变更与其 FTS5 索引更新必须在同一 SQLite 事务内完成；禁止出现"预览/搜索结果与库内数据不一致"的窗口。

### 2.3 错误处理总策略

- 主进程服务抛出带错误码的 `AppError`（错误码清单见 §7.4），经 IPC 透传至渲染进程；
- 渲染进程统一 toast 呈现用户可读的中文错误信息，技术细节写入主进程日志；
- 数据库打开失败/损坏：进入只读恢复引导页（提示备份文件位置），禁止在损坏库上继续写入。

## 3. 数据模型

### 3.1 表结构

```sql
-- VFS 节点表：目录与文件统一建模（软删除：deleted_at 非空即在回收站）
CREATE TABLE node (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_id     INTEGER REFERENCES node(id) ON DELETE CASCADE,  -- 根节点为 NULL
  node_type     TEXT    NOT NULL CHECK (node_type IN ('dir','file')),
  name          TEXT    NOT NULL,            -- 当前级名称（不含路径）
  virtual_path  TEXT    NOT NULL,            -- 物化完整路径，加速解析与展示（唯一性由下方部分唯一索引约束）
  mime_type     TEXT,                        -- 文件 MIME 类型，目录为 NULL
  size          INTEGER NOT NULL DEFAULT 0,  -- 文件字节数，目录恒为 0
  content       BLOB,                        -- 文件内容，目录为 NULL
  content_hash  TEXT,                        -- 内容 SHA-256，去重与变更检测
  created_at    TEXT    NOT NULL,            -- ISO 8601 本地时间
  updated_at    TEXT    NOT NULL,
  deleted_at    TEXT                              -- 软删除时间，NULL 表示未删除
);

-- 同目录重名约束（目录与文件共享命名空间）
CREATE UNIQUE INDEX idx_node_parent_name
  ON node(parent_id, name) WHERE deleted_at IS NULL;

-- 路径唯一约束（仅约束未删除行：软删行让出路径，支撑回收站让名与还原撞名语义 FR-VFS-06）
CREATE UNIQUE INDEX idx_node_virtual_path
  ON node(virtual_path) WHERE deleted_at IS NULL;

-- 目录快速下钻索引
CREATE INDEX idx_node_parent ON node(parent_id) WHERE deleted_at IS NULL;

-- 回收站视图查询索引
CREATE INDEX idx_node_deleted ON node(deleted_at) WHERE deleted_at IS NOT NULL;

-- 全文索引：FTS5 trigram，name 与 body 两列分别支撑文件名/内容搜索
-- 普通 FTS5 表（自存索引文本），由应用层在同一写事务中维护，rowid = node.id
CREATE VIRTUAL TABLE node_fts USING fts5(name, body);
```

### 3.2 数据规则

1. **根节点**：`id = 1, parent_id = NULL, virtual_path = '/'`，由迁移脚本创建，不可删除/重命名；
2. **路径规范**：分隔符一律 `/`；名称禁止 `/` `\` 与空字节，禁止 `.`、`..`；名称长度 1–255 字符；
3. **文件上限**：单文件 50MB，超限拒绝写入并返回 `E_VFS_FILE_TOO_LARGE`；
4. **FTS 同步**：文件内容的增删改与 `node_fts` 增删改同事务；目录变更仅影响 name 列联动更新其子树路径；
5. **时间戳**：统一 ISO 8601 字符串（本地时区含偏移量），`updated_at` 由服务层统一维护。

### 3.3 迁移与备份

- 结构迁移：`user_version`（PRAGMA）记录 schema 版本，启动时顺序执行增量迁移脚本，脚本幂等且首句开启事务；
- 备份：每日首次启动时复制数据库文件至 `backups/` 目录，滚动保留最近 7 份；设置页提供手动备份；WAL 文件在备份前执行 checkpoint 合并。

## 7. 接口契约

### 7.1 IPC 通道清单（渲染进程 → 主进程）

| 通道 | 语义 | 关键入参 | 返回/异常 |
| ---- | ---- | -------- | --------- |
| `vfs:list` | 列子节点 | `parentId 或 virtualPath` | 节点元数据数组 |
| `vfs:create` | 新建目录/文件 | `parentId, name, type` | 新节点；`E_VFS_DUPLICATE_NAME` 等 |
| `vfs:read` | 读文件内容 | `nodeId` | `{ content, meta }` |
| `vfs:write` | 写文件内容 | `nodeId, content` | 新元数据 |
| `vfs:rename` / `vfs:move` | 重命名/移动 | `nodeId, ...` | 受影响子树路径 |
| `vfs:trash` / `vfs:restore` / `vfs:purge` | 删除/还原/彻底删除 | `nodeId` | 操作结果 |
| `search:query` | 模糊搜索 | `keyword, filters, limit` | 命中列表（含高亮片段） |
| `io:import` / `io:export` | 导入/导出 | 源路径与目标节点 | 进度事件 + 结果 |
| `settings:get` / `settings:set` | 读写设置 | 键值 | 设置值 |
| `backup:create` / `backup:list` / `backup:restore` | 备份管理 | - | 备份列表/结果 |

事件类通道（主进程 → 渲染进程）：`vfs:changed`（树变更广播）、`io:progress`、`backup:done`。

### 7.2 `vfs://` URL 规范

- 格式：`vfs://local/<虚拟路径>`，如 `vfs://local/笔记/web/index.html`（2026-09-18 勘误：原空 host 形态 `vfs:///<虚拟路径>` 因 Blink 对 standard scheme 空 authority 做「首段提为 host」规范化而在导航链路不可达——Task 8 E2E 探针实证——身份形态改为固定 host `local`，拒绝语义不变）；
- 语义：等价于只读的 GET 资源请求；目录请求返回 `404` 语义错误码；路径含未删除校验，回收站节点不可被预览加载。

### 7.3 错误码（节选，全量在 `src/shared/errors.ts` 维护）

| 错误码 | 含义 |
| ------ | ---- |
| `E_VFS_NOT_FOUND` | 节点不存在或已在回收站 |
| `E_VFS_DUPLICATE_NAME` | 同目录重名冲突 |
| `E_VFS_INVALID_NAME` | 名称含非法字符/超长/为保留名 |
| `E_VFS_INVALID_MOVE` | 移入自身或后代 |
| `E_VFS_FILE_TOO_LARGE` | 超过单文件 50MB 上限 |
| `E_STORE_DB_DAMAGED` | 数据库损坏，进入恢复引导 |
| `E_IO_EXPORT_PATH_INVALID` | 导出目标不可写 |
| `E_BACKUP_FAILED` | 备份创建/还原执行失败（复制/替换等 IO 环节） |
| `E_BACKUP_NOT_FOUND` | 备份不存在或已被滚动清理 |
| `E_BACKUP_CORRUPT` | 备份完整性校验未通过，拒绝还原 |

### 7.4 日志规范

遵循全局规范：主进程按 info/warn/error 分级记录中文日志，含业务标识（节点 id、虚拟路径）；禁止打印文件内容全文与用户敏感信息。
